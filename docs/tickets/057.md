# 057: Counts on the filter buttons and keyboard shortcuts for the filters

- Type: task
- Status: done
- Priority: v1 if cheap, otherwise right after 055/056
- Depends on: [055](055.md)
- Related: [056](056.md)

Nice-to-have that makes the filter buttons much more useful while culling: how many photos each mode has in
the current folder, and keys to switch modes without the mouse.

## Counts

- `GET /api/photos/counts?dir=` returns the number of photos of the folder (the ones the grid shows) per mode:
  `all`, `unrated`, `rejected`, `rating:1`..`rating:5`, `fav`, `conflict` (one query with conditional sums;
  honors `one_star_is_unrated`).
- Buttons show the count (`Unrated 312`, `★3 41`); zero-count modes are dimmed but stay clickable.
- Counts update live as ratings change (the client adjusts them, consistent with [056](056.md)) and are
  refetched when the folder changes.

## Shortcuts

Grid view only (in the loupe the digit keys already rate). Proposal, to be decided: `Shift`+digit and
`Shift`+`X`/`U` (unrated) to pick a mode, avoiding `Alt`+digit which switches browser tabs. Shown in the
button tooltips.

## Result (2026-09-21)

- `GET /api/photos/counts?dir=` (`library.filter_counts`): one query built from the same conditions as the list, so a
  button's count always equals what it shows (a test compares every filter with and without `--one_star_is_unrated`);
  photos in hidden or other subfolders are not counted.
- Buttons show the count (`.n`), dimmed at 0 but clickable; loaded with the folder and refetched (debounced, in the same
  ordered queue as the edits, so after the server applied them) after every rating, fav, tag, batch and undo.
- Shortcuts, decided as proposed: in the grid only, `Shift`+`A` all, `Shift`+`X` rejected, `Shift`+`0` unrated, `Shift`+`1`..`5`
  exactly N stars (`Shift`+`1` is ignored with the 1-star flag); no `Alt`+digit (browsers switch tabs). Not active in the viewer
  or in a text field. Listed in the tooltips and the README.
- Tests: `tests/test_library_api.py` (counts equal the lists), `tests/e2e/test_ui.py` (counts, live updates and undo, another
  folder, shortcuts, tooltips, viewer/typing, flag). A flaky first version of the counts test pressed a key before the viewer
  had opened; the tests now wait for it.
