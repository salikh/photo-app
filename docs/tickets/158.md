## What's wanted

`catalog.py`'s `--metadata_json_fields=exif` group must compute the new `lens_model` field too, so a
tree cataloged by the tool gets the same shape of cache record photoapp's own scanner writes.

## Design

- `_EXIF_KEYS` gains `"lens_model"` (after `camera_model`, matching the tuple order ticket 157
  gives `read_image_metadata`); `_read_extra_metadata`'s tuple unpacking and its zip grow by one.
  Nothing else changes: the group already costs the one decode regardless, so the field rides along
  free, and `hash`-only default behavior is untouched (ticket 149).
- Update the `--metadata_json_fields` flag help string and the `exif` list in
  `tools/archive/README.md`, and extend the archive-tools test's expected key set.

## Outcome

Landed. `_EXIF_KEYS` gains `"lens_model"` (after `camera_model`, matching ticket 157's tuple
order), `_read_extra_metadata`'s unpacking/zip grow by one, and the `--metadata_json_fields` help
plus `tools/archive/README.md` name the new field. The `exif`-group test's expected key set now
includes `lens_model` (`tests/test_archive_tools.py`); `tests/test_archive_tools.py`,
