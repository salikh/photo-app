## What's wanted

Items of epic 156: read the lens used with each picture from EXIF, store it in the per-file
metadata cache and in a new `files.lens_model` column, and surface it through `photo_detail`.

## Design

- **`fileinfo.read_lens_metadata`** gains one return value: `lens_model`, the Exif sub-IFD
  `LensModel` tag (0xA434, `_EXIF_LENS_MODEL`), run through `_exif_str` like `Make`/`Model`.
  `read_image_metadata` appends it to its 10-tuple (becoming an 11-tuple), leaving the existing
  element order unchanged so callers that slice the head keep working. RAW files are covered by the
  same `img.getexif()` parse the function already does for focal length/camera make/model.
- **Migration**: `ALTER TABLE files ADD COLUMN lens_model TEXT;` — nullable, NULL when the file has
  no EXIF or no `LensModel` tag, same convention as the ticket 111 columns. No forced re-read in
  the migration itself; the metadata cache's `REQUIRED_KEYS` mechanism does the backfill (epic 156).
- **`scan.py`**: `lens_model` joins the `INSERT ... ON CONFLICT` in `_upsert_file`, the record
  dicts and tuple unpacking in `_scan_files` (both the cache-miss and cache-incomplete paths) and
  `import_single_file`, and the `UPDATE ...` in `_apply_move` (a moved file keeps its lens).
- **`metacache.REQUIRED_KEYS`** gains `"lens_model"`; because a record missing it is not "complete",
  the next scan re-reads and backfills every pre-existing record (ticket 111's own tested path).
- **`library.photo_detail`** selects `lens_model` alongside the other camera columns, so
  `/api/photos/{id}` carries it to the Files panel with no API-shape change.

## Outcome

Landed. `fileinfo.read_lens_metadata` now returns `(focal_length, camera_make, camera_model,
lens_model)` (LensModel 0xA434 from the Exif sub-IFD, `_exif_str`-normalized), and
`read_image_metadata` appends it to its tuple (11 elements; existing order unchanged, RAW covered by
the same Pillow EXIF parse). Migration adds nullable `files.lens_model TEXT`.
`scan._upsert_file`/`_scan_files` (both paths)/`import_single_file`/`_apply_move` carry the field,
`metacache.REQUIRED_KEYS` gains `"lens_model"` so the next `write_metadata_json` scan backfills
pre-existing records by re-reading each file once (ticket 111's own mechanism — no new backfill
script, as the epic decided), and `library.photo_detail` selects it.

Tests: synthetic-EXIF extraction in `tests/test_previews.py` (the tuple-unpack sites updated);
`tests/test_metacache.py` gains `test_lens_model_is_stored_and_written_to_the_cache` and
