# 212: `gphotos_upload` job

- Type: feature
- Status: done
- Priority: user request 2026-10-10
- Parent: [205](205.md)

## What's wanted

Queued once per export request; runs after that request's export jobs finish.

## Todo

- [x] Uploads in the grid order given in the request; append-only into the new or chosen album.
- [x] Progress 'uploaded N of M' in the jobs UI; per-file failures listed in the job result, the job still completes.
- [x] 'Retry failed' re-queues only the failures (safe: identical bytes dedupe on Google's side).
- [x] No album bookkeeping in the photo DB (Google Photos is authoritative). Depends on 209, 211.

## Done

`photoapp/gphotos_upload.py` (`run`: waits for the request's export jobs, uploads each chunk of 50 in parallel, one serial batchCreate per chunk in grid order, album created lazily and its id saved at once, failures in `options.failed`, progress in the new `jobs.note` column). `POST /api/export` takes `gphotos: {album_title | album_id}` and returns `upload_job`; `POST /api/gphotos/jobs/{id}/retry` re-queues just the failures; the Jobs page shows the note and a 'Retry failed' button. Tests: `tests/test_gphotos_upload.py`.
