# 142: Jobs page's job list shows the photo's path, linked to the photo

- Type: task
- Status: in progress
- Priority: user request 2026-09-29
- Related: [113](113.md) (`JobQueue.active()`, the `f.path` join pattern this reuses), [140](140.md)
  (the Jobs page this table lives on)
- Refs: `photoapp/jobs.py` (`JobQueue.list()`), `photoapp/static/pages.js` (`renderJobs`,
  `photoLink`)

## Problem

The Jobs page's per-job table (kind/file/state/error — the one place a failed job's error message
is visible) shows the raw numeric `file_id` in its "File" column, not the photo's actual path, and
it isn't a link. The user asked for the file's relative path instead, linked to that specific photo
in its album (opening the loupe there), matching how ticket 113's `Worker: ...` status line and the
loupe's "exported from" link already resolve a file to its path/photo.

## Design

- `JobQueue.list()` currently does a bare `SELECT * FROM jobs`. Add the same `LEFT JOIN files f ON
  f.id = j.file_id` pattern `active()` already uses, selecting `f.path AS path` and `f.photo_id AS
  photo_id` (both `NULL` for a `target`-scoped job like `scan_dir`/`prune_jobs`/`purge_trash`, or a
  `file_id` whose row is gone).
- `pages.js`'s existing `photoLink(path)` helper (already shared by the Activity/Attention pages)
  only links to the file's folder, not the photo itself. Give it an optional second `photoId`
  parameter that also sets `photo` on the href — reusing `loupe.js`'s existing "exported from" link
  pattern (`href({dir, photo: photoId})` opens the loupe on that exact photo). Existing callers
  (Activity/Attention) are unaffected (the parameter is optional, defaulting to no `photo`); only
  the Jobs page passes it.
- The job table's "File" column becomes `x.path ? photoLink(x.path, x.photo_id) : (x.target ||
  x.file_id)` — a `target`-scoped job (no `file_id` at all) still shows its target directory
  string, and a `file_id` whose file row is gone (or ungrouped, no `photo_id`) falls back to
  showing the bare id/path without a link rather than a broken one.
