# 245: deploy.sh health check probed the wrong host

- Type: bug
- Status: done
- Priority: user request 2026-10-19

`deploy/helper.py listen` ignored the whole `service.args` file because the seeded file starts with a
comment line (it only understood text starting with `PHOTOS_ARGS=`), so it reported the config default
`0.0.0.0` while the service bound `--host 192.168.1.11`. The script then polled `127.0.0.1`, found
nothing, and reported "did not become healthy" for a service that was up. `listen` now skips comment
lines. Test: `test_listen_reads_the_seeded_service_args_file_with_its_comment_line`.
