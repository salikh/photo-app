# 167: Self-heal existing records' lens without a full RAW re-read

- Type: task
- Status: done
- Priority: user bug report 2026-09-30
- Related: Epic [164](164.md); [166](166.md) (the cheap reader this calls), [162](162.md) (the
  staleness machinery this extends), [111](111.md) (the cache record shape)
- Refs: `photoapp/metacache.py` (`record_is_stale`, `index_lacks_keys`), `photoapp/scan.py`
  (`_scan_files`)

## What's wanted

A DNG/PEF scanned before ticket 166 has `lens_model = NULL` with an otherwise complete cache record,
so a scan reuses it and the Files pane stays empty. Existing rows must fill in without forcing a
full `read_image_metadata` re-read (which re-opens every RAW through LibRaw — hours across 29k DNG,
see ticket 163).

## Design

- **`metacache.record_lacks_lens(record)`** — True for a RAW record whose extraction otherwise
  worked (`camera_make` is set, `mime_type` is a RAW mime) but `lens_model` is `None`. Deliberately
  separate from `record_is_stale` (which triggers a full re-read): this one is fixed by a cheap
  MakerNote-only probe. `index_lacks_keys` also returns True for it, so the directory is reprocessed.
- **`_scan_files` cheap patch**: in the cache-reuse branch, when the record is complete and not
  `record_is_stale` but is `record_lacks_lens` and the file is RAW, call
  `fileinfo.read_pentax_lens(filepath)`; if it returns a name, patch `lens_model` and return the
  record with `was_read = True` (so it is rewritten). If it finds nothing, return the cached record
  unchanged — the file is reprocessed once per scan but never re-decoded. Only RAW files without a
  lens reach this path.
- No new command: the next scan of the directory fills the lens, and a later change to the same
  directory cannot revert it (the cache record itself now carries the name). The lens backfill is a
  side effect of the same `_scan_files` pass, so `backfill_exif` needs no change.

## Outcome

Landed. `metacache.record_lacks_lens` flags a RAW record (`image/x-adobe-dng`/`image/x-raw`) whose
extraction worked (`camera_make` set) but has no lens; `index_lacks_keys` returns True for it, and
`_scan_files`'s cache-reuse branch then calls `read_pentax_lens` (MakerNote only, never
`read_image_metadata`) and patches `lens_model` — so a scan fills existing DNG/PEF rows without the
hours of LibRaw re-reads that marking them `record_is_stale` would cost. Tests
(`tests/test_metacache.py`): the signature, and a stubbed DNG record patched with the full reader
asserted never to run.
