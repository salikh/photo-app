# 117: Multi-state filter buttons cycling between =, >=, <= and 3-column filter selector in loupe

- Type: task
- Status: done
- Related: [015](015.md), [016](016.md) (rating filters), [097](097.md), [098](098.md)
- Refs: `photoapp/static/index.html`, `photoapp/static/loupe.js`, `photoapp/static/app.js`

## What's wanted

Make each star filter button (`*1` .. `*5`) behave like a multi-state cycle:
- Default state: "all"
- Click on `*1` -> filter state `=1`
- Click again on `*1` -> filter state `>=1`
- Click again on `*1` -> filter state `<=1`
- Click again on `*1` -> filter state `=1`
- Clicking a different star button (e.g. from `=1`, `>=1`, `<=1` to `*2`) switches directly to `=2`.

In the Loupe view filter selector:
- Create a 3-column selection table/grid for each star value:
  - Column 1: `<= N`
  - Column 2: `= N`
  - Column 3: `>= N`

## Outcome

Landed. The filter grammar gained `rating>=N` and `rating<=N` alongside `rating:N`
(`library.filter_condition`, with `COUNT_FILTERS` extended so `/api/photos/counts` covers them, and
`filters.matches` mirroring the server). The comparators are ranges over the **1..5 star scale**, so
they exclude unrated (0) and rejected (-1), which keep their own filters.

In the grid, `filters.starButtonState`/`nextStarFilter` drive each star button: clicking cycles
`=N -> >=N -> <=N -> =N`, any other filter (or a different star) starts at `=N`, and the button's
label (`★N`, `★≥N`, `★≤N`) and `data-filter` follow its current state so its count badge is the
active state's count. Shift+N still means exactly N. In the loupe, the filter picker is now a
non-star row plus a 3-column grid per star value (`≤ N`, `= N`, `≥ N`, with per-option counts and
disabled state), still switching filter without losing the shown photo. Help text updated. Tests:
`test_library_api.py` comparator/counts, two e2e tests for the cycle and the loupe grid, and the
two filter-picker e2e tests updated to the new markup.
