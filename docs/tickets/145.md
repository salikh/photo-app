## What's wanted

Items 2 and 4 of epic 144: moving a batch of Photos (every live file + its sidecars) into a
destination directory inside `pictures_dir`, then scheduling a rescan of every directory touched.

## Design

### `photoapp/move.py` (new module, mirrors `trash.py`'s shape)

- `MoveError(Exception)` — a request that cannot be carried out; message is safe to show (same
  convention as `TrashError`/`ExportError`).
- `resolve_dest_path(pictures_dir, dest_dir, name, taken)` — numeric-suffix collision
  disambiguation (`name-2.ext`, ...) against both `os.path.exists` and an in-batch `taken` set of
  already-claimed relative paths. Not a reuse of `export.resolve_dest_path`: that function's
  "already an export of this same file" reuse case is meaningless here and would be actively wrong
  for a move (silently overwriting an unrelated file at a collision).
- `_move_file_and_sidecars(conn, settings, file_id, rel_path, dest_dir, taken)` — moves one file:
  - No-op (returns `None`) if `paths.dirname(rel_path) == dest_dir` already.
  - Computes the disambiguated destination via `resolve_dest_path`, `shutil.move`s the original,
    then (unlike `trash.py`) `UPDATE files SET path = ?` (not `missing = 1` — the file is still
    live, just relocated) and calls `thumbs.move_thumbnails`/`raw_preview_dng.move` so cached
    renders follow it instead of being silently orphaned (ticket 128's own machinery, reused).
  - Also moves `rel_path + ".json"` (the ticket 111 per-file metadata cache) and every
    `xmp_sidecars` row's file for this `file_id`, best-effort (a missing sidecar file is not an
    error — same as `trash._move_file_and_sidecars`) — their `xmp_sidecars`/on-disk `index.json`
    bookkeeping is deliberately left to the rescan this triggers (item 4), not hand-maintained here
    (see epic 144's Design overview for why).
  - Returns `{"from": rel_path, "to": new_rel_path}`, or `None` for the no-op case.
- `move_photos(conn, settings, photo_ids, dest_dir)` — `move_photo` for many Photos (mirrors
  `trash.trash_photos`): for each Photo, every live `files` row (any role, matching
  `trash_photo`'s "every live file", not just the representative), moved via
  `_move_file_and_sidecars` with a batch-shared `taken` set. A Photo whose every file was already
  in `dest_dir` reports no error and simply moves nothing (matches "a file already in the
  destination is a no-op" from epic 144, at Photo granularity). Returns `{"moved": [{"photo_id",
  "files": [...]}], "errors": [{"photo_id", "error"}], "source_dirs": {...}}` — `source_dirs` is
  the set of distinct directories any file actually moved *out of* (for the caller to schedule
  rescans of, alongside `dest_dir`).
- Commits once per Photo (matching `trash_photo`'s granularity), not once for the whole batch — a
  failure partway through a large batch leaves earlier Photos' moves durable, same reasoning as
  `trash_photos`.

### `photoapp/api.py`

- `GET /api/dirs/exists?dir=<rel>` — `{"exists": bool}` via `library._norm_dir` + `os.path.isdir`.
  Small and dedicated rather than folded into `/api/move`'s response, so the frontend can ask
  *before* committing to a request the user hasn't confirmed yet (ticket 147's create-folder
  modal) without a TOCTOU-prone error-string-matching dance on the move endpoint itself.
- `POST /api/move` — body `{ids: [photo_id, ...], target: str}`. Validates `target` with
  `library._norm_dir` (400 on `..`/escape, same as every other `dir` param); always
  `os.makedirs(dest, exist_ok=True)` — creation is gated entirely on the frontend side (the
  existence check + confirm modal, per item 1), not re-confirmed here, the same division of
  concerns `trash_photos_route` already draws between "the server enforces safety invariants" and
  "the client owns the UX confirmation." Runs `move.move_photos` synchronously (a same-filesystem
  rename is fast — no job queue needed, matching `trash_photos_route`'s own synchronous precedent),
  then enqueues one low-priority `scan_dir` job (ticket 076's existing kind, already handles a
  single directory non-recursively for a non-root target) per distinct directory in `source_dirs |
  {dest_dir}`, plus (ticket 146) a `link_exports` job if `dest_dir` starts with `Exported` (`==
  export.EXPORT_SUBDIR` or `startswith(export.EXPORT_SUBDIR + "/")`). Returns `move_photos`'s
  result plus `"scan_jobs"`/`"link_exports_job"` (job ids, mainly for tests).

### `docs/design/move.md` (new, mirrors `docs/design/trash.md`)

why file identity is preserved synchronously instead of relying on ticket 128's hash-matching
