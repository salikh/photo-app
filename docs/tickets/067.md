# 067: Arrow up/down to step the rating in the viewer

- Type: task
- Status: open
- Priority: user request 2026-09-22, implement now
- Related: [031](031.md) Loupe keyboard handling, [046](046.md) swipe up/down (same step semantics), [063](063.md)
- Refs: `photoapp/static/loupe.js` (`onKey`, `rateStep`, already used by swipe), `photoapp/static/rating.js` (`step`)

Add `ArrowUp` = rating +1, `ArrowDown` = rating -1 as keyboard shortcuts in the viewer, matching the swipe
up/down behavior of [046](046.md) (which already calls `rateStep(delta)` — this ticket only needs to call the
same function from the keyboard handler).

## Behavior (reuses what 046 already defined, so this should be small)

- One key press = one step along -1 (reject), 0, 1..5 (clamped at both ends), via the existing `step()` /
  `rateStep()` used by the swipe gesture and by `ratings.step` on the server.
- Un-reject (`ArrowUp` from reject) restores the previous star count if the server remembered one ([024](024.md)).
- With `--one_star_is_unrated` ([049](049.md)), 1 is skipped in both directions, same as swipe and the digit keys.
- Same optimistic update / revert-on-failure / "leaves the filtered view" behavior as every other rating change
  ([056](056.md)) — free, since it goes through the existing `setRating`/`rateStep` path.
- `ArrowLeft`/`ArrowRight` keep meaning navigate (unchanged); only Up/Down are repurposed, and only inside the
  viewer (`onKey`), not in the grid.
