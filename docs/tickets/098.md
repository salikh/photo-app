# 098: Export target moves inside the library, with collision-safe naming

- Type: task
- Status: open
- Blocked by: [097](097.md)
- Related: [096](096.md) (epic), [089](089.md) (the export feature this changes)
- Refs: `photoapp/export.py` (`default_target` — swaps `pictures_dir`'s basename for "Exported",
  sibling of `pictures_dir`; `validate_target` — currently *refuses* any target inside
  `pictures_dir`; `dest_path`/`within_dir` — mirrors `rel_dir`'s subfolder under the target, no
  collision check beyond that), `photoapp/static/export.js` (the modal defaulting to
  `default_target`'s result, per 089)

## Path change

`default_target(pictures_dir, rel_dir)` should return `pictures_dir/Exported/rel_dir` instead of
`{parent of pictures_dir}/Exported/rel_dir`. `validate_target` currently raises for *any* target
resolving inside `pictures_dir` (`"the export target cannot be inside {name}"`) — that check has to
carve out an exception for the new default (and, per the user's flexibility for the target field,
probably for any target under `pictures_dir/Exported` specifically, not `pictures_dir` in
general) while continuing to refuse exporting into some *other* part of the live library, which is
still not what this feature is for.

## Collision-safe naming

`dest_path` builds the destination filename as just `os.path.basename(thumbs.thumb_relpath(file_path))`
mirrored under `within_dir(rel_dir, file_path)`. Once exports accumulate in one library folder over
time (repeated exports, exports from different sessions/selections that happen to mirror to the
same subfolder, or the pre-existing content already in `/zoo/Pictures/Exported`), a destination
basename can collide with an unrelated existing file. Needs a strategy:

- Decide what "collision" means: same basename, different source file (real collision, needs a new
  name) vs. same basename, *same* source file re-exported (arguably fine to overwrite, or treat as
  already-exported and skip — depends on 097/099's linking design, since a re-export should
  probably reuse or refresh the existing DB link rather than create a second one).
- Decide the disambiguation scheme for a real collision — a numeric suffix loop (`name-1.jpg`,
  `name-2.jpg`, ...), a suffix derived from the source file's id/hash, or something else. Whatever
  is chosen needs to be deterministic enough that [099](099.md)'s "which file did this job just
  write" bookkeeping stays simple.
