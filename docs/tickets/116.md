# 116: Question: how should non-destructive crop interact with thumbnail generation and exports?

- Type: question
- Status: answered (2026-09-25)
- Blocks: [115](115.md) (unblocked)

## Context

Ticket 115 introduces non-destructive cropping for photos in the editing/loupe view. In the loupe view, the request specifies that cropped-out areas should be shown dark shaded.
However, it is open how cropped photos should appear in other views and generated thumbnails.

## Question

When a photo has non-destructive crop parameters saved:

1. **How should grid thumbnails (Thumb / Small / Medium / Huge) appear?**
   - **Option A: Show full photo with dark shaded crop margins** (consistent with the loupe strip view requirement).
   - **Option B: Generate thumbnails cropped to the selected rectangle** (standard gallery behavior so the user sees the intended composition in the grid).
   - **Option C: Uncropped in grid view, cropped in Medium/Huge full views, shaded in Loupe editor**.

2. **Does crop apply to RAW only, or both JPEG and RAW files?**
   - **Option A: Both JPEG and RAW** (generic photo editing crop).
   - **Option B: RAW files only** (integrated directly into RAW tuning settings).

## Answer

* Thumb size (standalone small thumbnail) should use crop and show only cropped content
* Medium/Huge (large or zoomed image) in loupe view should show the full image with cropped out areas shaded.
* Small thumbnail -- I'm not sure -- if using it in a grid, crop should be applied. If showing a single image, then cropped out areas should be shown shaded.

Question 2 was answered later (2026-09-25, asked again while implementing 115): **both JPEG and
RAW**. Crop is therefore a generic per-file setting (`files.crop_x/y/w/h`, `photoapp/crop.py`),
not folded into the RAW tuning settings.
