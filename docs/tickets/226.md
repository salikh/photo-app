## Design

- New `photoapp/edits.py`, modelled on `raw_settings.py`/`crop.py`: `get(conn, file_id)`,
  `normalize(doc)` (drops default values; an all-default document becomes `None`), `validate(doc)`
  (ranges below, raises `EditsError`), `set(conn, file_id, doc)` (writes `files.edits`, bumps
  `thumb_rev`, clears that file's thumbnails like `raw_settings.set`), `is_default(doc)`.
- Column `files.edits TEXT` (JSON), one migration in `db.py`.
- Document (all keys optional): `brightness` -100..100, `contrast` 0.5..2.0, `levels`
  `{black 0..254, gamma 0.2..5, white 1..255}` plus optional per-channel `levels_r/g/b`,
  `mono` `{weights:[r,g,b]}`, `sharpen` `{amount 0..300, radius 0.1..3.0 as % of the long edge /100}`;
  v1 additions per 225 (`saturation`, `auto`).
- `compile_lut(doc) -> (lut_r, lut_g, lut_b)`: composes all pointwise edits into one 256-entry table
  per channel (pure, unit-tested, the single definition of the maths).
- API: `GET/PUT /api/files/{id}/edits` (404/400 for a RAW or video, validation errors surfaced like
  raw_settings), `DELETE` to reset; the file JSON in library listings carries `edits` so the panel can
  show them. Edits never go into XMP sidecars (like crop/rotation); a rescan never clears them;
  a moved/renamed file keeps them (they live on the `files` row; check `move.py`/`scan.py` handling
  as done for `raw_*`).
