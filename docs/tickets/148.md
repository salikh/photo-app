## What's wanted

Item 3 of epic 144: `PHILOSOPHY.md` currently states plainly that "originals are never moved,
renamed, or deleted," true only because the one exception on record (`trash.py`'s move into
`.trash/`) is itself framed as the sole carve-out. Epic 144 adds a second kind of original-touching
write (moving a photo to another library folder), so the flat "never" is no longer accurate and
needs to become what was actually always meant: never *automatically* — only ever by explicit,
reviewable user action, and always a move, never an unlink.

## Design

Revise the paragraph (not just append a Findings note — this is the kind of stance shift
`PHILOSOPHY.md`'s own "So, going forward" section says earns touching this file, not just adding a
feature):

- Old: "So: **originals are never moved, renamed, or deleted.** The only writes this app makes into
  the library itself are XMP sidecars (atomically, after a first-seen backup) and, when a photo is
  rejected, a *move* into `.trash/` — never an unlink (see `docs/design/trash.md`)."
- New (shape, not final wording — write it in the file's own voice at implementation time): make
  the operative rule "no automatic/silent original-touching write, ever — only XMP sidecars write
  themselves; every move or deletion happens because a person clicked something that named it,"
  list `.trash/` (reject-and-delete) and the new folder-move (ticket 144) as the two *kinds* of
  user-initiated move this app performs, and link `docs/design/move.md` alongside the existing
  `docs/design/trash.md` reference.
- Leave everything else in that section (the rebuildable-database framing, `rating_by_hash`
  durability, epic 131) untouched — those stances aren't affected by this change.
