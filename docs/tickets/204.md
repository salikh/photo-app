# 204: Bug: iPad loupe showed the video shifted right with the still on the left (stale CSS)

- Type: bug
- Status: done
- Priority: user report 2026-10-09
- Parent: [184](184.md); Refs: `photoapp/api.py` (`RevalidatingStaticFiles`), `photoapp/static/index.html`

## Report

On iPad the loupe's video element was shifted right by half the width and the static thumbnail was
visible on the left; expected only the player, centered, with or without the files pane.

## Cause

Not a layout bug: the layout is right (checked at iPad sizes in Chrome, with and without the pane).
`index.html` linked `style.css?v=121`, a hand-bumped cache-buster that had stayed at 121 since ticket
121, and the app sent no `Cache-Control` for its static files, so Safari kept using an old stylesheet
from before the video rules existed -- the player and the still were both ordinary flex items side by
side (the player pushed right, the still left). New JS ran against old CSS.

## Fix

- `index.html` and everything under `/static/` are served with `Cache-Control: no-cache`: always
  revalidated (static files carry an ETag, so an unchanged file is a 304). The manual `?v=` is gone, so
  this cannot recur when CSS/JS change.
- Added a tablet-size e2e test of the player's geometry with and without the pane.

On the iPad: one reload is enough once the server is updated (the cached CSS is revalidated on the next
load; if Safari still holds it, pull-to-refresh or "Clear History and Website Data" once).
