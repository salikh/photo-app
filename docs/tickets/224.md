# 224: Research — client-side canvas vs baked thumbnails

- Type: research
- Status: done
- Priority: user request 2026-10-11
- Parent: [222](222.md)

## Question

Can the edits be applied in the browser canvas instead of recomputing thumbnails?

## Measured (headless Chrome, software rendering — no GPU on this box, so a worst case)

| | 1000x667 | 2000x1333 | 6000x4000 |
|---|---|---|---|
| JS `getImageData` + LUT + `putImageData` | 13 ms | 65 ms | 259 ms |
| canvas `filter = brightness() contrast() grayscale()` | 20 ms | 63 ms | 553 ms |
| canvas `filter = blur(2px)` (unsharp's expensive half) | 11 ms | 43 ms | 453 ms |
| (server Pillow LUT, for comparison) | 1.2 ms | 4.8 ms | 49 ms |

WebGL2 is available; on a real GPU a shader does a LUT and a blur-based unsharp in about a frame.

## Findings

- Client-side is **10-15x slower than the server** on this machine for the LUT, because it is software
  rendering plus a pixel copy per frame. On a laptop/phone GPU it would be faster, but that is not
  measurable here and the server path is already fast enough.
- **Server-side live preview is cheap**: a provisional render at Medium is ~35-45 ms in total (decode
  the cached Huge/Medium source ~15 ms + LUT 5 ms + unsharp 100 ms worst + encode 13 ms), the same
  shape as 094's `raw_preview` endpoint, debounced, which the RAW sliders already use. No client
  rendering code is required for the cheap edits.
- The client cannot replace baking: baked thumbnails are what the grid, filmstrip, exports and every
  other client (iPad, other tabs) show; computing per view would put the cost on every browse.
- A client-side WebGL path remains a **possible later optimisation for the live preview only**
  (instant slider response, no round trip), analogous to epic 102's LibRaw-Wasm for RAW. It would
  have to match the server's maths exactly (the LUT is easy to match; unsharp's kernel/radius
  semantics need care, as 106 found for RAW).

## Recommendation

Bake on the server (the user's primary design), live preview through a provisional server render
like 094. Defer client-side rendering; record it as a possible follow-up, not part of this epic.
