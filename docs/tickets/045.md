# 045: Swipe left/right to navigate pictures in a folder

- Type: task
- Status: open
- Blocked by: [061](061.md) (real-phone check)
- Parent: [043](043.md) Mobile UI
- Depends on: [044](044.md) Responsive layout, [027](027.md) Loupe view
- Refs: user request (b)

In the loupe, a horizontal swipe moves to the next/previous picture in the current folder
ordering (same order and preloading as the arrow keys).

Proposed mapping: swipe left = next picture, swipe right = previous (the usual photo-gallery direction).

## Todo

- [x] Gesture handling with Pointer Events (one code path for touch, pen and mouse drag), distinguishing horizontal from vertical swipes by dominant axis and a distance/velocity threshold
- [x] The image follows the finger and animates to the neighbor; snap back when below threshold
- [x] Reuse the loupe's preloading (next 3, previous 1) so a swipe shows an image immediately
- [x] Behavior at the first/last picture (rubber-band, no wraparound)
- [x] Do not conflict with pinch-zoom and with panning a zoomed image (swipe only when not zoomed, or at the pan edge)
- [x] URL-hash state keeps working (reload and back land on the same picture)
- [ ] Test on a real phone over the LAN

## Progress (2026-09-21)

`static/gestures.js` (Pointer Events, axis lock after 10px, 60px or fast-flick threshold) and the
loupe: the picture follows the finger, snaps back below the threshold, shows a toast at the first or
last picture (no wraparound), and swipes are off while zoomed. A drag never counts as a tap-to-zoom.
Verified with a 390px touch viewport in `tests/e2e/test_ui.py`. **Left open: try it on a real phone.**
