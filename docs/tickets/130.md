# 130: Organize the code for use by other users (config, install docs, dependencies, fresh-install tests)

- Type: enhancement (packaging / operability)
- Status: open
- Related: [001](001.md) (skeleton, flags), [042](042.md), [111](111.md) (flags that already exist),
  [073](073.md) (background worker flags)
- Refs: `photoapp/config.py`, `photoapp/__main__.py`, `photoapp/db.py` (`open_state`, `DB_NAME`),
  `start.sh`, `requirements.txt`, `README.md`, `docs/operations.md`, `tests/e2e/harness.py`

## What's wanted

Today the app runs only on the author's machine: defaults point at `/zoo/Pictures` and `/zoo/Thumbs`,
the flags live only on the command line, there is no install guide, `requirements.txt` mixes runtime and
test packages, and nothing checks that a brand-new checkout actually starts. Make it usable by someone
else on a fresh machine.

## Todo

- [ ] (1) Configuration extracted from hardcoded values
  - [ ] Every path is configurable: `pictures_dir`, `thumbs_dir`, `state_dir`, the sqlite database
    (new `--database`, default `<state_dir>/app.sqlite`), `hashes_db`; `~` and `$VARS` expand
  - [ ] Portable defaults instead of `/zoo/...`: `pictures_dir=~/Pictures`; `thumbs_dir` defaults to
    `<state_dir>/thumbs`; `state_dir` honours `$XDG_DATA_HOME`
  - [ ] A config file (TOML, keys are the flag names) found via `--config`, `$PHOTOS_CONFIG`,
    `./photos.toml`, `~/.config/photos/config.toml`; precedence command line > file > defaults; an unknown
    key or a wrong type is a clear error; applies to every entry point (server and the CLI tools)
  - [ ] `photos.example.toml` documents every key; the author's own `photos.toml` (gitignored) keeps the
    `/zoo` paths so `./start.sh` behaves as before
  - [ ] `host` and `port` come from `Settings`, not from `FLAGS` in `__main__`
  - [ ] Clear startup error when `pictures_dir` does not exist
- [ ] (2) Installation instructions for a new installation: `docs/install.md` (prerequisites, install,
  configure, first run with `--xmp_dry_run`, first scan, run as a service, upgrade, uninstall/backup),
  linked from `README.md`
- [ ] (3) Dependencies
  - [ ] `requirements.txt` = runtime only, with minimum versions; `requirements-dev.txt` = tests
    (pytest, httpx, playwright)
  - [ ] Python version requirement stated and checked by `start.sh`
  - [ ] Every third-party import in `photoapp/` is covered by `requirements.txt` (a test)
  - [ ] System prerequisites listed (none for the server; Chrome only for the browser tests)
- [ ] (4) Integration tests for a fresh install
  - [ ] Always-on: `python -m photoapp` from an empty `HOME` with only `--pictures_dir` creates the state
    dir, database and thumbs dir, serves `/api/health`, scans and serves a photo; config file, env
    variable and command-line precedence; bad config and missing pictures dir errors
  - [ ] Opt-in (`PHOTOS_TEST_INSTALL=1`): copy of the tracked files, `./start.sh` builds a new venv from
    `requirements.txt` and serves a sample library

## Notes

- The library's own data is never touched by these tests; they use temporary directories and a
  temporary `HOME`.
