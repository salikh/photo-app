# 044: Responsive layout for smartphone screens

- Type: task
- Status: open
- Parent: [043](043.md) Mobile UI
- Depends on: [026](026.md) Folder browser and grid, [027](027.md) Loupe view
- Refs: user request (a); docs/plans/photo-manager-plan.md §6

Good rendering on a phone (portrait and landscape). Do this while building 026/027 rather than
retrofitting: the layout has to be designed mobile-aware from the start.

## Todo

- [x] `<meta name="viewport" content="width=device-width, initial-scale=1">` and safe-area insets (notch)
- [x] Grid: column count adapts to width; thumbnail sizes chosen accordingly (`Thumb` vs `Small`)
- [x] Folder browser becomes a collapsible drawer/sheet on narrow screens instead of a side tree
- [x] Loupe uses the full viewport (`100dvh`, no browser-chrome overflow), filmstrip hidden or reduced on phones
- [x] Touch targets at least 44px; no feature that depends on hover or on a keyboard
- [x] On-screen buttons for actions that are keys on desktop (back to grid, undo, fav, tag entry)
- [x] Prevent accidental page zoom/scroll/pull-to-refresh inside the loupe (`touch-action`)
- [x] Check in a phone-sized emulated viewport (devtools) and once on a real phone over the LAN

## Progress (2026-09-21)

Done and covered by `tests/e2e/test_ui.py` at 390x800 with touch: viewport meta and safe-area
insets, auto-fill grid (3 columns at phone width), folders as wrapping chips instead of a drawer,
`100dvh` loupe with the filmstrip hidden under 700px, no horizontal scroll, every button/select at
least 44px high, on-screen rating/fav/tag/undo/close buttons, `touch-action` and
`overscroll-behavior` set on the stage. **Left open: check once on a real phone over the LAN**
(open `http://<host>:8080/` after `./start.sh`).
