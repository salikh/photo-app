Scan the whole `/zoo/Pictures` (847 GB, about 92k images) once into a real state directory, using
`--hashes_db` to avoid rehashing where possible. It takes a long time over the NAS (a directory of
800 files took about 15 minutes with hashing), so it is a background job and should be run by the
user or with the user's go-ahead. The scan only reads `/zoo/Pictures`; it writes only the state DB.

## Progress (2026-09-21)

- `python -m photoapp.fullscan --hashes_db=~/zoo.db` (read-only on the library, progress every 30 s,
  safe to interrupt and rerun) scans into the default state dir `~/.local/share/photos`.
- Measured: 2.2 files/s cold over the NAS (about 11 h for the library) before the thread pool;
  21 files/s on a 744-file folder with `--scan_workers=8`. Small directories parallelize less: the
  early years ran at 4-6 files/s. Started at low priority (`nice`/`ionice`) at 01:37; log in
  `~/.local/share/photos/fullscan.log`.
- Hashes come from `~/zoo.db` (159638 rows, all files, matching relative paths), so nothing is rehashed.
