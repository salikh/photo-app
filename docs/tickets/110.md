# 110: Thumb thumbnail stays stale after editing RAW tuning settings

- Type: bug
- Status: done
- Related: [085](085.md)/[094](094.md) (per-file RAW settings, the Save/commit flow),
  [107](107.md) (the compare/hover model this doesn't affect)
- Refs: `photoapp/static/loupe.js` (`saveRawSettings` — already cache-busts its own `ui.img`
  with `?r=` on Save, but does nothing for the grid cell or filmstrip thumbnail of the same
  photo), `photoapp/static/grid.js` (`makeCell`'s `<img src=imgUrl('Thumb', ...)>`, no
  cache-busting param), `photoapp/static/filmstrip.js` (`loadImages`'s `<img>`, same), `photoapp/
  api.py` (`cache = {"Cache-Control": "private, max-age=3600"}` on `/img/{size}/{file_id}`)

## Bug report (user, 2026-09-25)

"After editing the DNG parameters, the Thumb (smallest) thumbnail is not regenerated, or is not
reloaded, even after hard page reload."

## Root cause

The server side is correct — confirmed directly (both via the API and via a real Save through the
browser UI): `raw_settings.set` → `thumbs.clear` removes every cached size including Thumb, and
the next `/img/Thumb/{file_id}` request regenerates it with the new settings. The bug is client
-side, and has two parts:

1. `saveRawSettings` only refreshes `ui.img` (the loupe's own main image, with a `?r=` cache-bust)
   when the saved file is the one currently shown. It does nothing for the **grid cell** or
   **filmstrip** thumbnail of the same photo — both keep whatever `<img>` DOM node (and `src`)
   they already had, so nothing re-fetches at all when the user closes the loupe and looks at the
   grid again, regardless of what the server now has.
2. Even where a fresh request *would* happen (e.g. a real full page reload, rebuilding the grid
   from scratch), `/img/{size}/{file_id}`'s URL never changes for a re-tuned file — only the bytes
   at that URL do — and the response carries `Cache-Control: private, max-age=3600`. A browser
   that still holds that URL in its HTTP cache from before the edit can serve the stale copy for
   up to an hour, reload or not, unless the reload specifically bypasses the cache.

## Fix

Cache-bust the same way `ui.img` already does (`?r=` + a timestamp), for every place that shows
this file's Thumb and might already be in the DOM: the grid cell (`grid.js`'s new
`refreshCellThumb`) and the filmstrip's node for the current photo (`filmstrip.js`'s new
`refreshThumb` method), both called from `saveRawSettings` right alongside the existing `ui.img`
refresh, under the same "this is the file currently shown" condition.

## Repro note

Only reproduces when the tuned RAW file *is* the Photo's representative. A DNG+JPG pair defaults
to the camera JPG as representative (`grouping.py`'s `fix_representatives`), in which case tuning
the DNG's settings correctly changes nothing on screen — the grid/filmstrip/loupe all still show
the (unaffected) JPG. First reproduction attempt used a DNG+JPG pair and found no bug at all for
exactly this reason; the real repro needs a standalone DNG (or one explicitly set as
representative via "Show this"/cycle), which is also this project's more common real-library case
(most RAW files have no camera-JPG sibling at all).
