# 171: Fill `focal_length_35mm` for existing records with a cheap EXIF probe

- Type: task
- Status: open
- Priority: user request 2026-09-30
- Related: Epic [169](169.md); [170](170.md) (the field/column), [167](167.md) (the same cheap-patch
  shape for the lens)
- Refs: `photoapp/fileinfo.py` (`read_focal_length_35mm`), `photoapp/metacache.py`
  (`record_lacks_focal_length_35mm`, `index_lacks_keys`), `photoapp/scan.py` (`_scan_files`)

## What's wanted

Rows and cache records that predate the new column must fill in without a full `read_image_metadata`
re-read, which for a RAW means re-opening it through LibRaw (hours across 29k DNG — the same reason
ticket 167 exists).

## Design

- **`fileinfo.read_focal_length_35mm(filepath)`** — the standard tag only: `Image.open`'s Exif
  sub-IFD for a file Pillow can read, `read_exif_from_tiff` for a PEF. No `raw_size`/LibRaw, no
  hashing. Returns `None` when the tag is absent.
- **`metacache.record_lacks_focal_length_35mm(record)`** — True when the record has no
  `focal_length_35mm` key at all (a record written before this field). A record that has the key
  with value `None` is complete (the camera genuinely had no equivalent), so it is never re-probed.
  `index_lacks_keys` returns True for a directory containing one, so the scan reprocesses it.
- **`_scan_files`** cache branch: when the record is complete but lacks the key, set it from
  `read_focal_length_35mm` before returning the cached record (alongside ticket 167's lens probe).
  The returned record is upserted, so the DB column fills and the cache record is rewritten.
- **Not added to `REQUIRED_KEYS`**: that would make every pre-existing record "incomplete" and force
  a full metadata re-read of the whole library for one integer. The cheap probe is the backfill.
