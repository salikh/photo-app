# 112: Add sliders for additional raw parameters under a collapsible section

- Type: task
- Status: done (2026-09-25)

## What's wanted

Both LibRaw and its WASM version have quite a few DNG conversion parameters, so surface more tunable parameters to the user.
2 or 3 most important ones should be visible immediately (as it is now), and the rest should be hidden under a collapsible section / "zipper".

Candidate parameters from LibRaw / LibRaw-Wasm:
- Half-size demosaicing / fast preview mode
- Demosaicing algorithm selection (e.g. AHD, DCB, VNG, etc.)
- Noise reduction / chromatic aberration correction
- Saturation / contrast / tone curves (if available in bindings)

## Scope note

Any new parameter exposed must follow the epic 102 / ticket 106 & 109 rule:
Keep exact parameter parity between server-side `previews._postprocess_kwargs` and client-side `rawTuning.mapSettings`, verified on real DNG Bayer data.
In `loupe.js`, keep the primary 2-3 sliders directly visible and put advanced sliders inside a collapsible `<details>` / zipper element.

## Decisions made (2026-09-25, verified against a real Pentax K-5 DNG)

Chosen set (user selection): the "photographer set" of four controls, all under an "Advanced"
`<details>` zipper; the existing brightness/WB/highlight/exposure/shadow remain directly visible.

- **Demosaic algorithm** = LibRaw `user_qual` (rawpy `demosaic_algorithm`; LibRaw-Wasm `userQual`),
  restricted to the algorithms this LibRaw build ships: `1=VNG, 2=PPG, 3=AHD (default), 4=DCB,
  11=DHT, 12=AAHD` (AMAZE/LMMSE need the GPL demosaic packs, absent from both bindings). Column
  `raw_demosaic` INTEGER; NULL = AHD.
- **Noise reduction** = FBDD mode (rawpy `fbdd_noise_reduction`; LibRaw-Wasm `fbddNoiserd`),
  `0=off/1=light/2=full`. Column `raw_noise` INTEGER; NULL = off. (Wavelet denoise via rawpy
  `noise_thr`/WASM `threshold` was also viable but FBDD is the single more useful control.)
- **Saturation** = a **post-decode** adjustment, not native. LibRaw's `user_sat` was tested and
  rejected: it is a white-point/brightness override (lower = brighter), not a saturation
  multiplier, and the vendored WASM build's `color_data` comes back all-zero for the preview DNG,
  so it could not be made file-relative client-side anyway. Column `raw_saturation` REAL,
  `v' = luma + (v - luma)*amount` per channel with `luma = 0.299R+0.587G+0.114B`, range [0, 2],
  identity 1.0. Mirrored in `previews._apply_saturation` and `rawTuning.js`.
- **Contrast** = also **post-decode**, because a native gamma control failed the parity rule: the
  vendored **libraw-wasm 1.6.0 build silently ignores its documented `gamm` setting** (verified on
  the real DNG — byte-identical output for every `gamm` value, while `outputBps`/`userQual` do take
  effect), so `rawpy`'s `gamma=` could not be matched. Column `raw_contrast` REAL,
  `v' = 0.5 + (v - 0.5)*amount` per channel, range [0.5, 2.0], identity 1.0. Mirrored in
  `previews._apply_contrast` and `rawTuning.js`.
- Post-decode order (both sides identical): shadow lift → contrast → saturation.
- API/pending keys are unprefixed (`saturation`, `contrast`, `noise`, `demosaic`), matching the
  rest of the pending dict / `RawSettingsBody`; the DB columns are `raw_*`.
