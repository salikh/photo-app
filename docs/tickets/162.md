## What's wanted

An existing PEF's cache record was written before ticket 161: every `REQUIRED_KEYS` key is present
(all `None`) and the mtime/bytesize match, so a scan today reuses it unchanged. Make those records
be re-read once, so a scan fills in the real metadata without any manual step.

## Design

- `metacache.record_is_stale(record)` — True when the record shows the signature of a RAW the
  extractor could not read: `mime_type == "image/x-raw"` **and** `exif_date is None` **and**
  `camera_make is None`. Keyed on the record, not the filename, so it is general to any
  Pillow-unreadable RAW, not PEF specifically; documented as "re-read once, then the record carries
  real values (or is genuinely EXIF-less and costs one cheap re-read per scan)".
- `index_lacks_keys` also returns True if any named record is stale, so `_scan_subtree`'s
  directory-level skip check reprocesses a directory whose only change is a stale record.
- `_scan_files`'s cache-reuse condition (`cache_valid and has_all_keys(cached)`) additionally
  requires `not record_is_stale(cached)`, so the stale record is actually re-read rather than
  returned.
- The `mime_type == "image/x-raw"` guard keeps JPG/PNG/TIFF/DNG (which have their own mime types)
  out of the rule, so no unrelated directory is reprocessed.
