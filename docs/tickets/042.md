# 042: Decision: naming of new sidecars for RAW originals

- Type: decision
- Status: done
- Refs: docs/reqs/xmp-survey.md; docs/reqs/photo-manager-requirements.md (XMP handling); [019](019.md)

The requirements say new sidecars use `foo.xmp` next to RAW originals. The survey shows
15427 of 15429 existing sidecars are darktable-style full-filename (`foo.DNG.xmp`),
and only 2 are bare `foo.xmp`. Options:

1. Keep the requirement: new RAW sidecars are `foo.xmp` (Lightroom/Adobe convention;
   darktable would not pick them up and would create its own `foo.DNG.xmp`, giving two).
2. Use full-filename style `foo.DNG.xmp` for everything (matches the library and
   darktable; Lightroom would not pick it up).

Proposed default: option 2, since it matches what the library already uses, and existing
sidecars are edited in place either way. `xmp.preferred_sidecar_name` currently
implements option 1 and would change.

## Provisional default in use (2026-09-21)

Not yet answered by the user. Implemented as a flag: `--new_raw_sidecar_style=full|stem`, default
`full` (option 2, `NAME.DNG.xmp`). `stem` gives the original requirement (`NAME.xmp`). Existing
sidecars are edited in place either way, so only newly created RAW sidecars are affected.
Changing the answer is a one-word change of the flag default in `photoapp/config.py`.

## Decision (2026-09-21)

**`NAME.DNG.xmp`** (full-filename style, option 2). Confirmed by the user; it is the default of
`--new_raw_sidecar_style=full`. The flag stays as a switch to `stem` (`NAME.xmp`) if Lightroom
interop is ever wanted. Requirements and plan updated.
