# 120: Bug: Deletion confirmation page does not preserve "this folder and subfolders" mode

- Type: bug
- Status: done
- Related: [071](071.md), [072](072.md) (deletion flows), [057](057.md) (subtree / recursive views)
- Refs: `photoapp/static/app.js`, `photoapp/static/index.html`, `photoapp/api.py`

## Description

When clicking on "delete" mode from the "rejected" grid view with "this folder and subfolders" (recursive) enabled, suddenly the rejected photos disappear.
Instead, the confirmation view should keep the "this folder" vs "with subfolders" mode and show the rejected contents accordingly.

## Root cause analysis pointers

- Check URL parameter forwarding when navigating to delete confirmation: does it drop the recursive / subfolders flag (e.g. `recursive=1` or `subfolders=1`)?
- Check the deletion confirmation API request / query: is it querying files strictly in `dir` rather than `dir` + subdirectories?

## Outcome

Root cause: the Delete link built the confirmation URL with `hrefPage('delete-review', route.dir)`,
which dropped the `recursive` flag, and `route.parse` did not read one for `!` pages, so
`deleteReviewPage` always queried `/api/photos?dir=...&filter=rejected` without `recursive=1` --
a subfolder's rejected photos vanished from the review screen.

Fix: `route.hrefPage(page, dir, recursive)` and `route.parse` now carry `recursive=1` for `!`
pages; the header's Delete link (`app.js`) and the grid-selection hand-off (`grid.js`) pass the
current mode; `deleteReviewPage` fetches recursively when set and its "back to Rejected" link (and
scope text, "… and subfolders") keep the mode. The selection-review branch already carried the whole
route through `review.from`, so it was unaffected. Tests: a new e2e asserts the recursive Delete
flow lists the subfolder's rejected photo, says "and subfolders", and has a recursive back link;
the existing delete-review/selection e2e tests still pass.
