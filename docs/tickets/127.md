# 127: Rescan should honour the current folder's scope

- Type: enhancement
- Status: done (2026-09-26)
- Related: [126](126.md) (the Rescan button's crash), [051](051.md) (per-directory scans),
  [086](086.md) (the "This folder" / "+ subfolders" toggle)
- Refs: `photoapp/static/app.js` (`rescan`), `photoapp/api.py` (`/api/scan`), `photoapp/scan.py`
  (`ScanManager.start`, `scan`, `scan_all`)

## What's wanted

Pressing **Rescan** while in a subdirectory should rescan only that directory, not a wider tree.

Today `rescan(route)` posts `/api/scan?dir=<route.dir>` for any browse route whose dir isn't `.`;
`ScanManager.start` then calls `scan(scan_dir)` with `recursive=True`, so the *entire subtree*
below the current folder is walked. The grid's own toggle ("This folder" vs "This folder +
subfolders", ticket 086) already expresses the intended scope, but Rescan ignores it.

Intended behaviour:

- Rescan uses the same scope as the grid: only the files directly in the folder when "This folder"
  is active, the whole subtree when "+ subfolders" is.
- Rescanning a subdirectory never escalates to a whole-library `scan_all`; only the root's own
  Rescan does (and then also in its active scope -- root files only vs the whole library).
- A scan returned to the UI reports progress for exactly the requested scope.

## Design notes

- `/api/scan` needs a `recursive` query param (default matching today's behaviour is safest for
  other callers, but the button should pass `route.recursive`). `ScanManager.start(rel_dir,
  recursive=True)` and `scan(..., recursive=...)` already exist; `scan_all` is the full-library
  path and should stay reserved for the root + recursive case.
- The root (`.`) with "This folder" should scan only the files directly in the root, not the whole
  library.
- Keep the nightly scan / `fullscan` paths unchanged.
