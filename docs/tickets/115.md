# 115: Non-destructive crop mode in photo editing

- Type: task
- Status: done
- Related: [085](085.md), [102](102.md)
- Blocked by: [116](116.md) (answered)
- Refs: `photoapp/raw_settings.py` / `files` table, `photoapp/previews.py`, `photoapp/static/loupe.js`

## What's wanted

When in photo editing mode:
- Add a "Crop" button that enters non-destructive crop mode.
- Display an interactive crop grid/overlay over the image.
- Provide "Save" and "Discard" actions to conclude crop mode.
- Non-destructive persistence: store crop rect coordinates (x, y, width, height or normalized [0..1] fractions) associated with the photo.
- In loupe (strip) mode: if a photo has a non-default crop tuning, display the cropped area normally, and the cropped-out area shaded dark.

## Design considerations

- Storing coordinates: normalized [0..1] floats avoid dependency on pixel resolution differences across thumbnail sizes.
- Thumbnail generation vs display ([116](116.md) decision):
  - `Thumb` size (standalone small thumbnail in grid/filmstrip): crop and show only cropped content.
  - `Small` thumbnail: when used in grid view, crop is applied; when showing a single image, cropped-out areas are shown shaded.
  - `Medium`/`Huge` (large or zoomed view in loupe): show full image with cropped-out areas shaded dark.
- UI overlay: touch-friendly drag handles for mobile and mouse support on desktop.

## Outcome

Landed, for JPEG and RAW alike (question 116's part 2 answered "both"). `photoapp/crop.py` holds
the normalized rectangle on four nullable `files` columns (all NULL = whole frame; a whole-frame
rect is normalized back to NULL), `POST /api/files/{id}/crop` saves it and clears every cached
thumbnail, and `thumbs` applies the crop to `Thumb`/`Small` (rendering them straight from the
original, since larger cached sizes are full-frame) while `Medium`/`Huge` stay full. The loupe
gets a "crop" HUD button that opens an interactive rectangle with eight drag handles over the
full-frame image, plus Save/Discard; outside crop mode a `.crop-shade` layer darkens the
cropped-out area, positioned over the displayed image. `list_photos`/`photo_detail` carry the crop
so the client can shade without an extra request. Tests: `tests/test_crop.py` (validation,
normalization, pixel box, cropped vs full thumbnails, endpoint + cache clear, list/detail) and a
crop-mode e2e; design notes in `docs/design/thumbnails.md`.
