# 078: Document the sqlite database(s): location, schema, meaning

- Type: task
- Status: open
- Priority: not now (user request 2026-09-22)
- Related: every existing `docs/design/*.md` doc touches part of the schema already (photo-model.md
  the `photos`/`files` tables, ratings-and-xmp.md `xmp_sidecars`/`rating_by_hash`/`activity_log`,
  concurrency-and-jobs.md `jobs`, thumbnails.md `thumbs`) — this ticket is the missing single place
  that shows the whole picture and where each database actually lives on disk
- Refs: `photoapp/db.py` (`DB_NAME`, `CREATE_STATEMENTS`/`migrate`, `schema_version`),
  `photoapp/config.py` (`state_dir`, `hashes_db` flags), `photoapp/fileinfo.py` (reads
  `--hashes_db`), `photoapp/import_ratings.py` (reads an external `--metadata_db`),
  `docs/design/README.md` (states what belongs in this directory — see note below)

Add `docs/design/databases.md` documenting every sqlite database this app touches: where it lives
on disk, its schema, and what each table/column means. There is more than one:

- **The app's own state database** (`<state_dir>/app.sqlite`, `db.DB_NAME`) — the primary,
  read/write database: `files`, `photos`, `tags`, `xmp_sidecars`, `manual_links`,
  `rating_by_hash`, `activity_log`, `thumbs`, `jobs`, `dir_mtimes`, `meta`. This is the one that
  matters most and should get the bulk of the doc.
- **`--hashes_db`** (`hash_dir.py`-format, optional, read-only) — precomputed file hashes a scan
  reuses instead of re-hashing (`fileinfo.py`).
- **`--metadata_db`** (read-only, one-off) — an external Lightroom/darktable metadata database read
  by `import_ratings.py` for a one-time rating import; not part of normal operation.

## Note on where this fits

`docs/design/README.md` currently says this directory is for *why* something is the way it is, and
explicitly "not a restatement of what the code does; read the code ... for that" — a schema
reference is closer to "what" than "why". Worth deciding whether this doc:

- follows the existing docs' style (explain the reasoning behind the shape of the schema and where
  each database lives — e.g. why state is separate from `pictures_dir`, why `hashes_db` and
  `metadata_db` are external/read-only, why `jobs` is one shared table across kinds — plus a
  concise table of tables/columns/purpose as the reference part), which is the leaning, since it
  keeps one consistent style across the directory and this ticket's own "location, schema, meaning"
  ask is really "why is it laid out this way" as much as "what is in it"; or
- is treated as a deliberate exception (a pure reference doc), in which case `docs/design/README.md`
  probably needs a line acknowledging it as the exception.

Either way, update `docs/design/README.md`'s doc list once this is added.
