# 054: Do not show folders whose names start with a dot in the folder view

- Type: task
- Status: done
- Related: [026](026.md) Folder browser and grid, [048](048.md) Library scan
- Refs: user request; `photoapp/library.py` (`list_dirs`), `photoapp/static/grid.js` (folder chips)

In the folder view (the chips listing the subfolders of the current folder) do not list folders whose
name starts with a dot (`.`).

## What is in the library

Dot-named folders in `/zoo/Pictures` come from old programs, not from the user's own organization:
`.nu` (11 folders, thumbnails/previews of an old album tool), `.thumbnails` (3), `.webaxs` (87 images),
`.picasaoriginals` (Picasa's backup of the originals before an edit), `.comments`. The current scan holds
**136 image files** under them, which count as Photos and appear in folder counts.

## Open design points (decide while implementing)

- Scope of "do not show": only the chips in the folder view, or also the Photos in them. Proposal:
  hide the chips and leave the files out of the counts of the parent folders, so a folder's count
  matches what its grid can reach; the files stay in the database (scans are unchanged).
- Direct access: a URL such as `#/2001/new-epoch/.nu` still works (nothing is deleted), it is only
  not linked from the folder view. Proposal: yes.
- Should the rule also apply to any path segment below the current folder, for example a dot folder
  inside a hidden folder (it is unreachable anyway), and to the top level (`.something` in the root)?
- `.picasaoriginals` may hold the only copy of an unedited original. Hiding it is what was asked; if it
  ever matters, a setting to show hidden folders could be added later (not part of this ticket).

## Todo

- [x] Check on the real library: `2001/new-epoch` and `2002-CA` show no dot folders, and the counts of `2016/2016-life-studio` drop by the 87 `.webaxs` files

## Result (2026-09-21)

Implemented in `library.list_dirs` (server side; no frontend change needed): dot-named folders are not
listed and their Photos are left out of the counts of the folders above them, by looking only at the
directory part of each path. Decisions taken as proposed: hidden folders stay reachable by path; files
stay in the database and scans are unchanged; the rule applies at every level; a file whose own name
starts with a dot is not affected. On the real library no listed folder starts with a dot (checked four
levels deep), `2001/new-epoch` and `2002-CA` show no dot folders, and `2001/new-epoch/.nu` still opens
(7 Photos). Tests: `tests/test_library_api.py` and a browser test.

Note: ticket 054 was first only written up, not implemented, so a restarted app still showed the folders
until this change; a restart is needed to pick it up.
