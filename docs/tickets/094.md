## Current behavior (085) and the problem

Every slider tick (`onchange`) POSTs the full settings row to `/api/files/{id}/raw_settings`, which
writes `files.raw_*` and calls `thumbs.clear` for *every* cached size of that file — a global,
immediate commit with no distinction between "trying a value" and "keeping it." Dragging a slider
is therefore as expensive and as permanent as clicking a (nonexistent) Save button, and there's no
way to see before/after side by side without re-dragging back and forth.

## What the user wants instead (2026-09-24)

1. **Provisional rendering, not global regen**: adjusting a parameter regenerates only a
   provisional/preview thumbnail with the new parameters — it must not clear or touch the real
   cached sizes (`thumbs` table + files under the thumbs dir) or `files.raw_*` until committed.
2. **Compare hotkey**: a key that overlays the current (committed) rendering and the new
   (provisional) rendering at the same position — two images, z-index/visibility swapped by the
   hotkey — so the user can flip back and forth to judge the change.
3. **Leave room for browser-local rendering**: if adjusting brightness/WB/highlight-recovery in the
   browser (canvas/WASM, on the already-downloaded preview image) turns out to be fast enough for
   some/all of these settings, the architecture should allow swapping the provisional-render source
   from a backend round trip to an in-browser one later, without a redesign. Not implemented now —
   just don't paint into a corner.
4. **Explicit Save button**: commits the pending parameter values to the database and triggers the
   real backend thumbnail regeneration (today's `set_raw_settings` behavior) — this becomes what
   Save does, not what every slider tick does.

## Design notes (decided while implementing, 2026-09-24)

- **Provisional render contract**: `GET /api/files/{id}/raw_preview?bright=...&wb_mode=...&size=Medium`
  (`photoapp/api.py`). Renders straight from the original with whatever pending settings are in the
  query string, at `half_size=True` for responsiveness, and returns the JPEG bytes directly with
  `Cache-Control: no-store` — no `thumbs` table row, no file under `thumbs_dir`, no `files.raw_*`
  write, ever. `raw_settings.validate`/`to_columns` (new, factored out of `raw_settings.set`) give
  it the same input validation as the commit path without persisting anything.
- **Which size to preview**: always `Medium` — what the loupe shows non-zoomed (093's shape did not
  end up mattering here, since the preview path bypasses `thumbs.make` entirely).
- **Debounce**: sliders use `oninput` (fires continuously while dragging) updating local `pending`
  state and the visible number label immediately; a 200ms `setTimeout` per file, cleared and
  restarted on every tick, actually fires the `raw_preview` request (`loupe.js`'s `schedulePreview`/
  `requestPreview`). Setting `ui.tuning.src` directly (not a manual fetch+blob) lets the browser's
  own image-loading naturally supersede a stale in-flight request when a newer one is set.
- **Compare hotkey mechanics**: 'c', loupe-only, press-and-hold (keydown hides the provisional
  overlay to reveal the committed image underneath; keyup restores it) — a hold reads better than a
  toggle for "flip back and forth," and holding is simpler to reason about than a stateful toggle
  interacting with Save/Discard/navigation. `ui.tuning`, a second `<img>` absolutely positioned over
  `ui.img` (new `.stage img.tuning` CSS), carries the provisional render; hidden while pinch-zoomed
  (093-unrelated zoom.js transform doesn't apply to it) and restored on zoom exit.
- **Discard on navigate-away**: turned out to need no cleanup at all, precisely because nothing is
  ever written anywhere by the preview path — `discardPending()` just clears the debounce timer and
  hides/blanks `ui.tuning`. Called from `show()` (photo navigation) and `closeFiles()` (panel
  closed); `files.raw_*` was never touched to begin with.
- **Browser-local rendering**: noted as the natural next step for `raw_preview` specifically (not
  the commit path) in `docs/design/thumbnails.md`'s new section; not implemented.
