# 070: vlog(1..7) logging in the populate_thumbs tool

- Type: task
- Status: done
- Priority: user request 2026-09-22, implement now
- Related: [066](066.md) Background low-priority population of /zoo/Thumbs with dcraw
- Refs: `photoapp/populate_thumbs.py`, `photoapp/thumb_populate.py`

Add `absl.logging.vlog(N, ...)` calls to the populate_thumbs tool (the CLI entry point and
`thumb_populate.py`), so a `--verbosity=N` run gives visibility at the right granularity without
touching the default (non-verbose) output.

## Guideline (as given by the user)

- vlog(5) or vlog(7): an individual file operation that completed normally (finer detail -> 7).
- vlog(3): events worth a user's attention -- progress markers, unexpected-but-handled conditions
  on a file (e.g. a fallback path taken).
- vlog(1): detailed statistics on the whole run or a big part of it.
- Actual errors or anything worth fixing stay at `logging.info`/`.warning`/`.exception` (non-vlog),
  unchanged.
- Main goal: `--verbosity=3` alone should be enough to see what the batch job is doing at a
  granularity of seconds to a minute; everything else scales up/down from there.

## Todo

- [x] `thumb_populate.py`: vlog(7) per dcraw subprocess invocation; vlog(5) per size written

      (unexpected condition on a file)
- [x] `thumb_populate.py` `Populator._handle`: vlog(5) summary once a file's job finishes (which

- [x] `thumb_populate.py` `Populator.enqueue_missing`: vlog(1) stats on what was found
- [x] `populate_thumbs.py`: turn the periodic queue-counts report into vlog(3) (already on a
      seconds-to-a-minute cadence via `--report_seconds`, matches the level-3 guideline exactly)
- [x] Quick manual check with `--verbosity=3` and `--verbosity=7` on a small `--limit`

## Result (2026-09-22)

Added vlog(7) around each dcraw subprocess call, vlog(5) per size written (both the RAW/dcraw and
Pillow paths), vlog(3) for the fallback-to-half-size-render condition (bumped up from an
under-classified vlog(1)) and for the periodic queue-counts report (was `logging.info`, now on
`--verbosity=3`), and vlog(1) for a per-size missing-file breakdown in `enqueue_missing` and a
final-counts summary at the end of the run. Also added a non-vlog `logging.warning` if the final
counts show any failed jobs (was silent before -- failures were only visible on the Jobs page).

Existing test `test_populate_thumbs_command_fills_gaps_and_reports_progress` asserted on the
periodic report string, which moved off the default verbosity; updated it to pass
`--verbosity=3`. Manually verified `--verbosity=7` output end to end (see the ticket's PR/commit
for a sample). All of `tests/test_populate_thumbs_cli.py` and `tests/test_thumb_populate.py`
pass.
