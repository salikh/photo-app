# 143: Attention page links go straight to the photo, not its album

- Type: task
- Status: in progress
- Priority: user request 2026-09-29
- Related: [142](142.md) (same `photoLink(path, photoId)` pattern, added there for the Jobs page)
- Refs: `photoapp/static/pages.js` (`attentionPage`, `photoLink`)

## Problem

The Attention page's "Sidecars that disagree" and "Sidecars behind a newer rating" tables link each
row via `photoLink(c.path)`, which (per ticket 142) only opens the row's *folder*, not the specific
photo. The user asked for a direct link to the photo itself, matching what ticket 142 already did
for the Jobs page.

## Design

No backend change needed: `/api/attention`'s `conflicts` and `sidecars_behind` rows already select
`p.id` (the photo id) alongside `path`/`rating` (`api.py`'s `attention()` route). `pages.js`'s
`photoLink` already gained an optional `photoId` parameter in ticket 142 — `attentionPage` just
needs to pass `c.id` through at both call sites.

`orphan_sidecars` is unaffected: those rows are sidecars with no matching `files` row at all
(`file_id IS NULL`), so there is no photo to link to. `ambiguous_recovery`'s `photo_id` column is
plain text today, not a link at all (not an existing album-link to fix) — left alone, out of scope
for this ticket.
