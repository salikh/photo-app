## What's wanted

A read-only export, from this machine's live `app.sqlite`, of exactly the two things a comparison
against another copy needs — without requiring that other machine to open this app's sqlite file
directly (a different schema version, a locked/WAL file, or simply "no Python environment for this
app" should not be blockers):

1. **Catalog**: for every non-missing `files` row, its `path` and content `hash` (plus `bytesize`
   for a cheap sanity check). This machine's current, authoritative "what do I have."
2. **Decisions**: the full `rating_by_hash` table (hash, rating, fav, `rated_at`) — every reject
   (`rating == -1`) and every keep/pick, independent of whether the file behind it is still present,
   moved, or long since purged from `.trash/`. This is the durable answer to "was an absence here a
   decision."

Format: JSONL (one row per line), gzip-friendly, matching the existing `manual_links.jsonl`
convention rather than inventing a new one. A single command, e.g.:

    python -m photoapp.export_catalog --state_dir=... > catalog.jsonl

writing both kinds of row (tagged, e.g. `{"type": "file", ...}` / `{"type": "decision", ...}`) to
one file, or two flags for two output files — pick whichever keeps [135](135.md) simplest.

Incrementalism is not needed on this side: exporting the whole `files`/`rating_by_hash` tables is a
cheap, single sqlite scan (thousands of rows, not millions of files to re-hash) — the expensive,
must-be-incremental side is building the *target* copy's catalog ([133](133.md)'s kept
`catalog.py`, unchanged, already does that).
