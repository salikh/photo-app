report/script generation (option A/B territory) for every bucket, reviewable before anything

activity-log-worthy change would be, even though this runs outside the live server).

somewhere the next scan picks up normally (no special-casing needed in `scan.py` — a plain file at
a plain path), preserving the target copy's relative directory structure the way `move_to_trash`
mirrors it for `.trash/`. Do not invent a new "pending import" state in the database; a copied-in
file becomes a completely ordinary, unrated file the next time the library is scanned.

Verify against a real comparison, not just synthetic test trees, before calling this done — build
two small temp libraries, diverge them a rejected file and a never-seen file, and confirm all three
buckets come out right end to end.
