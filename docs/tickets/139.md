## What's wanted (user request 2026-09-28)

A top-level document explaining the philosophy and assumptions behind this project -- not how to
run it (today's `README.md` already covers that), but why it is shaped the way it is: the
non-obvious design stances that recur across the codebase (e.g. "originals are never moved,
renamed or deleted," "move, never unlink," per-file settings vs. per-Photo, durable hash-keyed
decisions, the sqlite-database-as-rebuildable-cache model, single-user/LAN/no-auth by design) and
the assumptions about the library itself and how it's used that motivated them.

## How this is meant to be done

The user explicitly asked for a `grilling`-skill session with them before writing this -- the
content should come from actually interrogating the user's own thinking, not from Claude
summarizing the codebase's comments back at them. The session should still take the code strongly
into account (it's the record of what was actually decided and why, e.g. `docs/design/*.md`,
ticket "Findings" sections, `docs/tickets/131.md`'s own reasoning) as material to grill *against* --
checking stated philosophy against what the code actually does, not starting from a blank page.

## Grilling session outcome (2026-09-28)

19 questions across several rounds, all resolved; two real corrections surfaced along the way, both
folded in:

- **No built-in auth was on track to be mis-stated as a non-goal** ("not for public internet
  exposure"). It isn't one: authenticated remote access is a real goal, satisfied by a private,
  OAuth-authenticated HTTPS proxy in front of this app, not by this app itself. `docs/operations.md`
  and the requirements doc both flatly say "LAN only, no authentication" today with no mention of
  that layer -- this was genuinely undocumented anywhere in the repo before this ticket.
- **"How this got built" was going to name only Claude Code.** Also actively used: OpenCode with
  DeepSeek Flash, and Google Antigravity with Gemini Flash.

Settled shape (see `PHILOSOPHY.md` itself for the result): a new, separate top-level
`PHILOSOPHY.md` (not a `README.md` rewrite, not an auto-loaded `CLAUDE.md`), first person, four
interleaved constraint-and-belief threads (data-safety archive, no-auth-as-boundary, durable
process/multi-tool record, what changed along the way), a precise non-goals section, single-user
reconciled with ticket 130's portability work as "one operator per deployment" rather than a
contradiction, and a closing decision-rule. Living document: a future ticket whose Findings shift
one of these stances touches this file too, the same way `docs/design/trash.md` gets amended
alongside later tickets.
