# 095: Shift+Click range selection in the grid

- Type: task
- Status: done
- Priority: not now (user request 2026-09-24)
- Refs: `photoapp/static/grid.js` (`makeCell`'s `onclick`, ~line 84-91 — currently treats
  `e.shiftKey`/`e.ctrlKey`/`e.metaKey` identically, all three just call `toggle(id)`; `toggle`,

  modifiers), `photoapp/static/state.js` (`state.selected` — a `Set`, no ordering; needs a new
  "last selected"/anchor field), `photoapp/static/app.js` (`clearSelection`'s Escape binding,

Today, Shift+Click, Ctrl/Cmd+Click, and clicking a cell's own ✓ button (or any click while
touch-friendly `state.selecting` mode is on) are all exactly the same: `toggle(photo.id)` on just
that one photo. There's no concept of a "last selected" anchor, so Shift+Click can't do the usual
file-manager thing — select every photo between the last one you touched and the one you just
Shift+Clicked.

## What's wanted

Shift+Click extends the selection from the **last selected photo** to the newly clicked one,
selecting every photo in between (in the grid's current display order — `state.photos`, which
follows the active sort/filter). Plain click and Ctrl/Cmd+Click keep today's single-toggle
behavior.

## Design decisions (made while implementing)

- **Anchor**: the Explorer/Finder convention — the anchor is the last *plain*/Ctrl/Cmd click
  toggle, fixed across a run of Shift+Clicks (Shift+Click, then Shift+Click again further down,
  both extend from the *same* original anchor, not from wherever the previous Shift+Click landed).
  Kept as a module-level variable in `grid.js` (`selectAnchor`), not on `state` — it's pure
  grid-selection UI state, nothing outside `grid.js` needs it.
- **No anchor yet**: falls back to a plain single toggle of the clicked photo, which then becomes
  the anchor for the next Shift+Click.
- **Replace, not union**: Shift+Click replaces the selection with the anchor..clicked range.
  Combining with Ctrl+Shift for additive multi-range selection is not implemented — out of scope
  unless asked for.
- **Ordering**: computed over whatever's currently in `state.photos`. If the anchor or the clicked
  photo isn't in it (`indexOf` returns -1 — in practice only reachable if a page hasn't rendered a
  cell that got clicked, which shouldn't happen through the UI), falls back to a plain toggle
  rather than guessing.
- **Anchor reset**: cleared in both places `state.selected.clear()` already runs in `grid.js`
  (`loadFolder`, `clearSelection` — the latter is also what Escape and `toggleSelecting`'s
  turn-off already call), so a stale anchor from a previous folder/filter can't leak into a new
  Shift+Click.
- **The ✓ button**: also honors Shift — same `selectRange`/`toggle` split as the cell's own click.
