# 152: Files panel's "exported from" link shows the source's relative path

- Type: task
- Status: done
- Priority: user request 2026-09-29
- Related: [099](099.md) (`exported_from_file_id`, the "exported from" link this changes)
- Refs: `photoapp/library.py` (`photo_detail`), `photoapp/static/loupe.js` (`openFiles`'s
  `exported_from` link)

## What's wanted

In the loupe's Files panel, the "exported from" link currently reads `<dir> (photo <id>)` (e.g.
"2020/trip (photo 123)"). Show the source file's relative path instead (e.g.
"2020/trip/IMG_0001.jpg"). The link's target is unchanged — still `dir` + `photo_id`, jumping to
that Photo in its original folder — only the displayed text changes.

## Design

`library.photo_detail` already queries the source file's `path` (to derive `dir` via
`paths.dirname`) but discards it — add `"path": src["path"]` to the `exported_from` dict it
returns. `loupe.js`'s link text becomes `f.exported_from.path` in place of
`f.exported_from.dir + ' (photo ' + f.exported_from.photo_id + ')'`; the `href` stays exactly as
it is (`{dir: f.exported_from.dir, photo: f.exported_from.photo_id}`).
