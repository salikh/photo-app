# 236: (-) and (+) tap areas beside every slider in the adjustment panes

- Type: task
- Status: done
- Priority: user request 2026-10-12
- Related: [235](235.md), [228](228.md), [085](085.md)

## What's wanted

"In raw and jpeg adjustments panes, add tap areas to the left and right of slider (like this:
(-) ......v...... (+)) to make it easier to make small adjustments on ipad, where fine movements of
sliders are hard."

## Todo

- [x] a (-) and a (+) button either side of each slider, one step per tap (hold repeats), same code
      path as dragging (preview, pending state)
- [x] tests

## Result

Every slider of the adjustment panel (RAW and JPG share it, 235) has a 36 px **−** and **+** button on
either side: one slider step per tap, repeating after a 450 ms hold, going through the slider's own
input handler (preview, dirty state). Pointer Events, so it works with touch; keyboard activation
works too. Test: `test_plus_minus_buttons_step_a_slider_by_one_step_and_repeat_when_held`.

## Follow-up (2026-10-12): fit on a phone

"(-) slider (+) does not fit into one line on android." On a narrow screen (≤ 699 px) the label now
has its own line and "− slider + value" share the next one (slider shrinks, 32 px buttons, fixed-width
value). Root cause found on the way: the mobile `.files-panel { width: 100% }` and
`.stage.panel-open { padding-right: 0 }` rules sat *before* the base rules and lost to them, so on a
phone the panel and stage were 420 px wide (the desktop panel width) on a ~390 px screen — they now
come last. Test: `test_slider_rows_fit_on_one_line_on_a_phone`.

## Follow-up 2 (2026-10-12): iPad

The one-line row rules were phone-only (≤ 699 px); the 420 px side panel on an iPad still wrapped
the "+" button. The label-on-its-own-line / flexible-slider rules now apply at every width. Test:
`test_slider_rows_fit_on_one_line_in_the_ipad_side_panel`.
