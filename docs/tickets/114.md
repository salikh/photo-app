# 114: Recent job activity reporting columns on the Jobs page

- Type: task
- Status: done
- Related: [064](064.md), [113](113.md)

## What's wanted

On the "Jobs" page, replace the separate summary line "last minute, last hour, last day" with a new
structured group of columns in the background jobs table:
- Queued
- Running
- Done/Failed (all time, effectively 1 week because of job cleanup retention)
- Done/Failed (1 day)
- Done/Failed (1 hour)
- Done/Failed (1 minute)

## Outcome

Landed. `JobQueue.progress()` now gives every `by_kind` entry all-time state counts plus per-window
done/failed counts (`done_last_day`/`failed_last_day`, `..._last_hour`, `..._last_minute`), so one
`/api/jobs` response drives the whole table; the top-level `completed` buckets are unchanged. The
Jobs page drops the old "Last minute/hour/day" summary paragraph and renders a two-row grouped
header: Kind, Queued, Running, then Done/Failed for all time, the last day, the last hour and the
last minute. Tests in `tests/test_jobs.py` (per-kind window aggregation, updated progress fixtures)
and the Jobs-page e2e check.
