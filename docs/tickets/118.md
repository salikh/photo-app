# 118: Bug: Initial client-side RAW rendering image is displayed with incorrect orientation

- Type: bug
- Status: open (filed 2026-09-25)
- Related: [102](102.md), [105](105.md), [106](106.md)
- Refs: `photoapp/raw_preview_dng.py`, `photoapp/static/rawTuning.js`, `photoapp/static/loupe.js`

## Description

When switching to show the thumbnail based on DNG image, the thumbnail is shown correctly.
However, after the first edit to settings sliders, the client-side re-rendered image is initially shown with the orientation tag ignored.
After a few edit repeats, the image orientation is restored to normal.

## Root cause analysis pointers

- Check LibRaw-Wasm settings: does `render()` in `rawTuning.js` pass `flip` or `user_flip` orientation correctly on first render?
- Check canvas rotation / CSS transform in `loupe.js`: is orientation transform reset or unapplied on the newly rendered canvas/blob until a subsequent event triggers layout?
- Check if EXIF orientation metadata in the generated preview DNG is being parsed or stripped on first decode.
