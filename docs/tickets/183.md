# 183: deploy.sh: install the app as a systemd service

- Type: task

## What's wanted

A script that deploys the app to a fixed location and runs it as a systemd service. The app is pure
Python (no compile step), so "build" reduces to a dependency check. Decided in a /grilling session.

## Design (agreed)

- `sudo ./deploy.sh [--dry-run] [--install-deps] [--user=NAME]`. The target user comes from
  `$SUDO_USER` (or `--user`); refuses to run as a real root login. All user-owned work (venv, copy,
  config seeding, jj lookup) runs as that user via `sudo -u`, so nothing ends up root-owned.
- Install location `/opt/photos` (created and chowned to the user): `app/` (copy of `photoapp/` +
  `requirements.txt`, `rsync -a --delete`, no `__pycache__`), `.venv/`, `DEPLOYED_REV` (jj change id +
  timestamp). Rollback = check out the older revision and redeploy.
- Dependencies: create `/opt/photos/.venv` if missing; compare against `requirements.txt`
  (`pip install --dry-run`); if anything is missing, print the `pip install -r` command and exit
  non-zero. `--install-deps` runs it.
- Config outside the release, seeded only when absent, never overwritten, in
  `~user/.config/photos/`: `config.toml` (from `./photos.toml`, else `photos.example.toml`), `env`
  (from `./ENV`, systemd `KEY=value` syntax, mode 600), `service.args` (`PHOTOS_ARGS=...`, the
  author's flags: host 192.168.1.11, port 8080, `--v=5`, load/mem thresholds).
- Unit `photos.service` generated from `deploy/photos.service.in`: `User=`, `Nice=19`,
  `IOSchedulingClass=idle`, both `EnvironmentFile=`s, `RequiresMountsFor=` (pictures_dir and
  thumbs_dir from config.toml), `After=network-online.target`, `Restart=on-failure`, journald logs,
  no sandboxing (the app writes sidecars/trash into the library). Runs the venv python directly, not
  `start.sh`.
- Activate: `daemon-reload`, `enable`, `restart`. Refuses if the port is held by something other than
  the service. Then polls `is-active` + an HTTP GET for ~30 s; on failure prints
  `journalctl -u photos -n 20` and exits non-zero. `--dry-run` prints the actions only.
