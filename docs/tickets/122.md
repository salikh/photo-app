# 122: Free option in "filter by tag" to type any tag

- Type: enhancement
- Status: open (filed 2026-09-26)
- Related: [087](087.md) (fav and tag filter buttons in folder view), [123](123.md) (dot-tags unhide hidden directories)
- Refs: `photoapp/static/filters.js`, `photoapp/static/app.js`, `photoapp/static/style.css`

## Description

In the folder/browse view header (ticket [087](087.md)), the tag filter button / dropdown (`select.tag-filter`)
currently only offers the tags present among photos in the current view ("aspects" / facets populated
via `/api/photos/tags`).

Besides these aspects, provide a free-form option where the user can enter any arbitrary tag. On
click/selection of this option, a form or input prompt appears allowing the user to type any tag.
Submitting the form activates filtering by that tag (e.g. `tag:<typed_tag>`).

This capability is notably required for ticket [123](123.md) (dot-tags unhiding hidden directories):
because dot-directories are excluded by default, their tags do not appear as aspects in the dropdown,
making this free-form entry the primary way for a user to initiate a dot-tag filter.

## UX & Design Details

- **Trigger / Option**:
  - In the tag filter dropdown (`select.tag-filter`), include an entry such as "Custom tag…" or "Other
    tag…" (e.g. `<option value="__custom__">Other tag…</option>`) in addition to the default
    `tag: …` and the scoped aspect tags.
  - Alternatively, if the control is styled/rendered as a button or popover, provide a dedicated action
    to type a tag.
- **Input Form / Dialog**:
  - When the option is selected, display an input form (modal, dialog, or popover) with a text field for
    the tag name.
  - Autofocus the input field.
  - Support `Enter` to submit/apply, `Escape` to cancel.
  - Include "Filter" and "Cancel" buttons.
- **State & Routing**:
  - On submit with non-empty input, navigate to the filtered route `tag:<typed_tag>`.
  - When an arbitrary tag is active that is not among the current view's aspects, `applyTags` should
    still display the active tag in the selector (e.g. `<option value="tag:foo" selected>tag: foo</option>`)
    and mark the selector active (`.on`).
  - If canceled, restore the previous selector value without triggering navigation.
- **Backend Compatibility**:
  - The backend (`photoapp/library.py`, `TAG_FILTER_RE`) and frontend matcher (`filters.matches`)
    already support arbitrary `tag:NAME` filtering. No backend changes needed.
