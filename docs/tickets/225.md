## Context

Research (223, 224) shows every proposed edit is cheap except unsharp at full size. These are the
choices that are the user's to make; each has a recommended default and the build can start on the
defaults.

## Questions

1. **Settings for v1** — brightness, contrast, levels (black/gamma/white), per-channel levels,
   monochrome, unsharp (the recommendation in 223). Add **saturation** too (cheap, and the RAW panel
   already has it)? Add an **auto-levels** button? *Recommended: yes to both, they cost almost nothing.*
2. **Unsharp at Huge** costs ~1 s once per edited file (background job, cached). Accept, or skip
   sharpening at Huge and only bake it into Thumb/Small/Medium? *Recommended: accept; Huge is only
   rendered when someone zooms or exports.*
3. **Which files get edits**: JPG only, or every non-RAW still (PNG, TIFF, HEIC)? *Recommended: every
   non-RAW still Pillow can open.* RAW keeps its own sliders; a later ticket can make the same edits
   available on RAW.
4. **Storage**: one nullable JSON column `files.edits` holding the canonical edit document
   (NULL = unedited; easy to extend, one validation point), versus one nullable column per setting
   like `raw_*`. *Recommended: the JSON column.*
5. **Exports and Google Photos upload** use the edited render (the original JPG is still never
   changed). *Recommended: yes, with the existing "export original bytes" behaviour untouched for
   files without edits.*
