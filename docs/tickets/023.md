## Results (2026-09-21)

Tool: `python -m photoapp.survey [--state_dir=...]` (read-only).

**Your scan (`2001`, `2026`): nothing to survey.** 1675 files, 1161 Photos (514 with several files),
but zero XMP sidecars in those two directories (the sidecars in this library are from 2008 onwards).

**Sample instead: `2022/2022-01-ny`** (scratch copy of an earlier scan, not the state directory):
455 Photos (347 DNG+JPG pairs), 437 sidecars, none orphaned.

- 413 Photos have one sidecar; **12 have two, and all 12 disagree**: the DNG's sidecar says 1 star
  (darktable's default, see 049) and the JPG's says 2 (once) or 3 (11 times), i.e. a real rating.
- In all 12 the newest sidecar is the JPG's, so "newest wins" picks the deliberate rating here.
- Fav: no disagreements.

**Observation for the decision:** the requirements write ratings to the *original's* (DNG) sidecar
only. In these 12 the real rating lives on the JPG's sidecar; a write would go to the DNG sidecar and
become the newest, so it wins, but the JPG sidecar keeps the old value and the conflict badge stays.
Alternative: write to the sidecar that currently holds the winning rating (falls back to the
original's when there is none). Please decide: keep "original only" or switch. The first two survey
todo items are done for this sample; the library-wide run is still pending (048).

## Decision

- If there are both DNG and JPG files, then write the rating XMP for both files, so that the rating
  changes in sync in Darktable.
- In v2, we'll create a function to delete DNG files for saving space, most likely for rating=1,
  at that point keeping the rating in the XMP attached to JPG file is good.
- When reading ratings, keep the "newest win".
