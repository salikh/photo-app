# 058: Move the reject button to the left of the rating buttons

- Type: task
- Status: open
- Related: [055](055.md) filter buttons, [031](031.md) loupe HUD, [032](032.md) batch rating, [044](044.md) phone layout
- Refs: `photoapp/static/loupe.js` (`renderHud`), `photoapp/static/grid.js` (`renderSelectionBar`), `photoapp/static/style.css`

Put the reject button (✖) on the **left** of the rating buttons (☆ 1 2 3 4 5) instead of after the `5`.

## Today

- Loupe HUD: `☆ 1 2 3 4 5 ✖` followed by `♥ tag ↶ files ✕`.
- Grid selection bar: `☆ 1 2 3 4 5 ✖` (`Link…`, `Clear` after).
- The reject key `X` and the swipe mapping are unchanged by this ticket.

## Target

- Loupe HUD: `✖ ☆ 1 2 3 4 5` then `♥ tag ↶ files ✕`, the reject and rating buttons kept together as one
  group, ordered from reject through unrated to five stars (the same order as the ratings, -1 to 5).
- Grid selection bar: the same order.
- With `--one_star_is_unrated` ([049](049.md)) the group is `✖ ☆ 2 3 4 5` as before, only the position of ✖ changes.

## Design points

- **Consistency with the filter row** of [055](055.md): it is currently proposed as `All · Unrated · Rejected
  · ★1..★5`. To mirror this order it would become `All · Rejected · Unrated · ★1..★5`; decide when doing 055
  (small change either way; do both together if 055 is not done yet).
- **Accidental rejects on a phone:** ✖ is now at the left edge where the thumb rests on many phones; keep
  the visible gap from `☆` and the 44 px targets, and rely on undo (`↶`) as today. Check on a real phone
  (the real-device checks are on hold).
- Highlighting of the active state (`on` class) and tooltips stay as they are.
