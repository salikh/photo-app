## What's wanted (as given)

When the Files pane shows the focal length as `NNmm`, also show the 35mm full-frame equivalent in
parentheses, e.g. `35mm (52mm)`. This needs a new metadata field and a new database column.

## Design overview (detail in each child ticket)

- **One new integer field, `focal_length_35mm`**, from the standard EXIF tag `FocalLengthIn35mmFilm`
  (0xA405, Exif sub-IFD, type SHORT). Verified on the real library: 35 mm → 52, 18 mm → 27, the PEF
  43 mm → 64, exactly what `exiftool -FocalLengthIn35mmFormat` prints.
- **Extraction rides the existing readers.** `read_lens_metadata`/`read_image_metadata` gain the
  field from the same `img.getexif()` parse; `read_exif_from_tiff` (the PEF fallback) reads 0xA405
  too. `read_image_metadata`'s tuple grows by one at the end, so existing slices keep working.
- **`files.focal_length_35mm INTEGER`**, nullable (NULL when the tag is absent), migration; carried
  through `_upsert_file`/`_scan_files`/`import_single_file`/`_apply_move`, `library.photo_detail`
  and `catalog.py`'s `exif` group. No new endpoint.
- **Existing rows fill without a full RAW re-read** (ticket 171): the field is a standard EXIF tag,
  so a cheap `read_focal_length_35mm` (Pillow, or the TIFF fallback for PEF — never LibRaw) can
  patch a record that predates the column, exactly the ticket 167 shape. The key is deliberately
  **not** added to `metacache.REQUIRED_KEYS`: that would make every old record "incomplete" and
  send the whole library (92k files, 29k RAW) through a full `read_image_metadata` re-read for one
  integer; the cheap probe only ever reads EXIF.
- **Display** (ticket 172): `formatFocalLength(mm, mm35)` becomes `35mm (52mm)` when both are
  present, `35mm` when only the real focal length is, and `cameraMetaText` passes the new field.

## Non-goals

- **Deriving the equivalent from the sensor crop factor.** The camera already writes 0xA405; no
  sensor-size table is introduced. A file lacking the tag simply shows the plain focal length.
- **Sorting/filtering by the equivalent.** Display only, as asked.

## Outcome

Done — 170-172 all landed. `focal_length_35mm` (EXIF 0xA405) is extracted by both the Pillow and
TIFF-fallback readers, stored in a new nullable `files.focal_length_35mm` column, carried through
scan/detail/catalog/backfill, and shown as `35mm (52mm)`. Existing records fill via the same cheap
EXIF-only probe pattern as ticket 167 — deliberately not through `REQUIRED_KEYS`, which would have
forced a full LibRaw re-read of every RAW for one integer. Verified against real files (52 / 27 /
64 mm). Full non-e2e suite green (475 passed, 3 skipped; one pre-existing flaky scan-manager test
failed once in a full run and passed on rerun); Files-panel e2e passes.
