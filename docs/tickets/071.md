# 071: vlog(1..7) logging in the scan and in-line thumbnail paths

- Type: task
- Status: done
- Priority: user request 2026-09-22, implement now
- Related: [070](070.md) same guideline, applied to the populate_thumbs tool first
- Refs: `photoapp/scan.py`, `photoapp/thumbs.py`, `photoapp/previews.py`, `photoapp/api.py`
  (`/img/{size}/{file_id}`, the `raw_render` job)

Extend [070](070.md)'s vlog guideline to the two remaining code paths that generate/scan without
going through the populate_thumbs tool: the directory scanner (`scan.py`, run by `ScanManager` /
`NightlyScan` from the running server, and by the standalone scan command) and the server's
in-line thumbnail generation (the `/img/{size}/{file_id}` route's on-demand render, and the
`raw_render` background job that falls back to a full LibRaw decode).

## Guideline (same as 070)

- vlog(5) or vlog(7): an individual file operation that completed normally (finer detail -> 7).
- vlog(3): events worth a user's attention -- progress between directories, unexpected-but-handled
  conditions on a file (a fallback path taken, a preview that could not be used).
- vlog(1): detailed statistics on the whole run or a big part of it.
- Actual errors / anything worth fixing stay at `logging.info`/`.warning`/`.exception` (non-vlog),
  unchanged.
- `--verbosity=3` alone should be enough to see what's happening at a granularity of seconds to a
  minute; everything else scales from there.

## Result (2026-09-22)

`scan.py`: vlog(7) per file scanned/hashed and per unchanged-directory skip; vlog(5) per sidecar
synced; vlog(3) per directory actually scanned ("progress between directories", the guideline's
own example) and when files are newly marked missing; vlog(1) end-of-subtree stats (both `scan()`
and each `scan_all()` step now get one, computed as a before/after delta on the shared `Progress`
so a whole-library run's per-step numbers stay correct).

`thumbs.py`: `make()` now logs a vlog(7) cache hit or a vlog(5) fresh render, and its `Unsupported`
fallback moved from an under-leveled vlog(2) to vlog(3) (same bucket as 070's fallback bump).
`render_raw_sizes()` (background full-decode) gets vlog(3) on total failure and vlog(5) on
success. `index_existing()` (scan-time reconciliation) gets vlog(7) per file and a vlog(1) total.

`previews.py` (`embedded_preview`/`render`) previously failed silently; every failure/skip path
(LibRaw error, unsupported thumb format, too-small preview) is now vlog(3), and a success is
vlog(7).

`api.py`: the `raw_render` job logs a vlog(5) completion summary (errors already surfaced via
`jobs.py`'s `logging.exception`, unchanged). The `/img/{size}/{file_id}` route logs vlog(7) per
request and for a Huge-from-original hit, vlog(3) when a RAW has to be deferred to the background
job (expected/handled), and a non-vlog `logging.warning` when nothing at all is available (a real
gap the previous code silently 404'd on).

Removed a `thumb_populate.py` vlog(5) line (ticket 070) that duplicated `thumbs.make()`'s new
logging for the non-RAW branch.

Verified with a `TestClient`-driven scan and `/img/...` request at `--verbosity=3` and
`--verbosity=7`: the right lines appear/disappear at each level, and the periodic/per-file
messages line up with the guideline's granularity. Full suite: 264 passed, 5 skipped.
