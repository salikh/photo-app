## What's wanted

Decided: no dedicated "videos" button. Videos carry the implied `video` tag (185), so `tag:video`
already works. This ticket compares two cheap ways to expose it and keeps the better one: (A) a
`video` entry in the existing tag/filter dropdown (plus `-tag:video` style hiding if exclusion
exists); (B) a chip in the existing filter bar that merges with another control (e.g. the rating or
kind selector). Build both behind a temporary switch, look at them with the user, delete the loser.

## Outcome

The two variants turned out to be complementary rather than exclusive, and neither adds a control, so
both were built and kept (undo is deleting a few lines each): (A) `library.tags_in_view` also offers
the implied `video` tag, so the existing tag dropdown lists "video (N)" with a count that equals what
selecting it shows; (B) the tag chips in the loupe HUD (real and implied, including the `video` one) are
clickable and switch the view to `tag:<name>`. If you prefer only one, say which; the other is a
small removal.
