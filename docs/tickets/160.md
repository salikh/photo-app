## What's wanted (as given)

Support `.PEF` (Pentax RAW) as a RAW format. It is *already* listed in `fileinfo.RAW_EXTENSIONS`
and `IMAGE_EXTENSIONS`, and the parts that go through LibRaw already work on it: `read_raw_size`
reports the real 3008x2008 dimensions, `thumbs`/`previews` render, and `raw_preview_dng` generates
the client tuning DNG (verified read-only against a real PEF). What does **not** work is EXIF
metadata: unlike a DNG (TIFF-based, which Pillow opens), a PEF is a Pentax-compressed TIFF that
Pillow cannot identify at all (`UnidentifiedImageError`), so `read_image_metadata` returns `None`
for date, aperture, shutter speed, ISO, focal length, camera make/model and lens.

Measured on the real library: **147 PEF rows, every one with `exif_date`, `aperture`,
`shutter_speed`, `iso`, `focal_length`, `camera_make`, `camera_model` and `lens_model` all NULL.**
That is the actual gap.

## Design overview (detail in each child ticket)

- **Read EXIF straight from the TIFF/IFD structure, without decoding the image.** A PEF's EXIF is
  ordinary TIFF IFD data (IFD0 + the Exif sub-IFD); Pillow only fails because it tries to decode
  the Pentax-compressed pixel strip. `PIL.TiffImagePlugin.ImageFileDirectory_v2` parses those IFDs
  fine once the byte order from the file header (`II`/`MM`) is set. A new
  `fileinfo.read_exif_from_tiff(filepath)` does exactly that and returns the same values the
  Pillow path already extracts, reusing `parse_exif_date`/`_exif_rational_to_float`/`_exif_str`.
  `read_image_metadata` calls it when `Image.open` raises **and** the file is RAW.
- **Existing rows self-heal.** A PEF's cached record predates the fallback: it has every
  `REQUIRED_KEYS` key (all `None`) and a valid mtime/bytesize, so today a scan reuses it and never
  re-reads. A small, documented staleness rule treats such a record as incomplete — a RAW record
  whose `mime_type` is the generic `image/x-raw` with no EXIF at all — so `index_lacks_keys` and
  `_scan_files` re-read it once; after the fix it carries real values and is cached normally.
  Keyed on the *record*, not the extension, so any future RAW Pillow cannot open heals the same way.
- **A backfill command makes it immediate.** The just-over-147 files could wait for the nightly
  scan, but `backfill_exif.py` already exists for exactly this "fill old rows without a full
  rescan" job; it is taught the fallback and to write the whole EXIF set, so
  `python -m photoapp.backfill_exif` fills PEF (and any other missing) rows at once.
- **No new format needs adding anywhere.** `RAW_EXTENSIONS`, grouping's `is_raw`, thumbnail naming
  (`X.PEF.jpg`), sidecar conventions and the RAW tuning UI already accept `.pef`; this epic only
  makes its metadata real. `image/x-raw` stays the mime fallback.

## Non-goals

- **Other RAW formats Pillow cannot open.** None are present in this library (DNG and TIFF parse
  fine); the record-based staleness rule and the TIFF fallback are general, but nothing else is
  validated here.
- **A PEF-specific mime type** (`image/x-pentax-pef`). Cosmetic; `image/x-raw` is what every
  unknown RAW already gets.
- **Writing/renaming PEF, or changing its rendering.** Only metadata is in scope.

## Outcome

Done — 161-163 all landed. `.PEF` was already RAW everywhere else (dimensions, thumbnails, tuning);
the missing piece was EXIF, since Pillow cannot open a PEF. `fileinfo.read_exif_from_tiff` now reads
IFD0 + the Exif sub-IFD directly, so `read_image_metadata` returns real date/aperture/shutter/ISO/
focal/camera/lens for a PEF; `metacache.record_is_stale` makes the next scan re-read the existing
all-None records (147 in the real library), and `backfill_exif` fills them immediately (and now
writes the full EXIF set). No new format entries, endpoint, or rendering change.

Full non-e2e suite green (461 passed, 9 skipped, with `REAL_PEF` set); the real PEF reads
`('2008-02-16 18:25:54', 4.5, 0.125, 200, 43.0, 'PENTAX Corporation', 'PENTAX *ist DL', None)`.
