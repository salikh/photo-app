# 235: One set of adjustments for JPG and RAW, with the same basic / advanced split

- Type: task
- Status: done
- Priority: user request 2026-10-12
- Related: epic [222](222.md) (non-RAW edits), [085](085.md)/[094](094.md) (RAW tuning), [230](230.md)

## What's wanted

"Synchronize the editing options between JPG and RAW, in particular, make all the options available
for jpeg editing also available in raw mode. Also try to have a similar split between visible by
default and hidden under 'advanced' (It's very confusing now because the sets of adjustments is very
different between raw and jpg)."

## Todo

- [x] inventory both panels, decide the common list and the basic/advanced split
- [x] RAW rendering applies the JPG edit set (levels, per-channel, contrast, brightness, saturation,
      mono, sharpen) after the RAW conversion; storage, preview, thumbnails, exports
- [x] one shared panel layout in the loupe
- [x] tests, docs

## Result

One panel (`adjustControls` in `loupe.js`) for both kinds, same basic / Advanced split and the same
labels; a RAW now also has black point, midtones, white point, monochrome, sharpen, sharpen radius,
auto levels and red/green/blue levels (the edit document, `files.edits`, applied after the RAW
conversion — server `render_raw_sizes`/`make`/`raw_preview`, `POST /api/files/{id}/edits` accepts a
RAW). Brightness / Contrast / Saturation are one slider each, bound to the RAW conversion's own
parameter on a RAW (so there is not a second, confusing brightness); Contrast moved to basic in the
RAW panel to match. One Save stores both the RAW settings and the edit document; S / A (230) copy both.
Previews: local LibRaw-Wasm when no edit is set, the server's `raw_preview` (with `edits`) otherwise.
Tests: `test_edits_apply_to_a_raw_file_in_thumbnails_and_raw_preview`,
`test_raw_panel_has_the_same_adjustments_as_a_jpg_and_saves_them`.
