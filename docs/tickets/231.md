# 231: Google Photos album list looks empty for ~15 s in the export dialog

- Type: bug
- Status: done
- Priority: user report 2026-10-11
- Parent: [205](205.md)
- Related: [213](213.md)

## Report

"'Choose existing' when exporting to Google Photos does not work, and the album list is empty, even
after I uploaded quite a few albums." Follow-up from the reporter: the list is populated later.

## Findings

Not a functional bug. Measured against the real account: `GET /v1/albums` returns about **10 albums per
page regardless of `pageSize=50`**, so listing 10 albums took **12 sequential requests, ~15 s**; the
endpoint did that on every call (and again on every name keystroke), and the dialog showed an empty
`<select>` with no sign of progress. Scopes and token were fine.

## Fix

- Server: the album list is cached and fetched by a background thread ; `/api/gphotos/albums` answers
  at once with the cached list plus `loading` and `error`, `?refresh=true` forces a refetch, and an
  export that will create an album marks the cache stale. A failed refresh keeps the last good list.
- Dialog: shows "Loading albums… (can take ~15 s)" (or the error, or "No albums made by this app yet")
  instead of an empty list, polls every 1.5 s while loading, ignores superseded responses.

## Follow-up (user request 2026-10-11)

"Remove refreshing the album list in the background. I do not want my app constantly talking to the
Google Photos API." Then, clarified: loading in the background *of the Export dialog* is fine, but not
in the general background of using the app. Result: the TTL refresh is gone. Google is contacted only
by one listing that starts when the Export dialog opens (`/api/gphotos/status`, which only the dialog
calls) or when the dialog asks for the albums; the result is cached until restart, an export that
creates an album, or an explicit `?refresh=true`. Nothing runs on a timer and ordinary browsing never
touches Google (test `test_google_is_contacted_only_when_the_export_dialog_opens_and_only_once`).
The background *thread* only runs that single listing without blocking the request; the dialog
polls the local server, not Google, while it runs.
