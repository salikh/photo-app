## What's wanted

A job that sends a picture for AI rating with caching: an unchanged prompt must not send the picture
again; the prompt's content hash is part of the cache key.

## Design

- Migration: `ai_responses(image_key, prompt_hash, model, answers JSON, created_at,
  PRIMARY KEY (image_key, prompt_hash, model))`; `files.ai_score REAL`, `files.ai_score_version
  TEXT`.
- `image_key` = `<files.hash>:<thumb_rev>` (the rendition sent depends on the content *and* on
  crop/RAW tuning, which bump `thumb_rev`; fall back to `id:<file id>` when there is no hash). The
  same image content in two folders therefore shares one response.
- `ai_rating.rate_file(conn, settings, file_id, transport=None)`:
  1. load + register the prompt (175);
  2. cache lookup on `(image_key, prompt.hash, settings.ai_model)`;
  3. miss → read the file's Medium thumbnail (generating it if absent), `gemini.rate_image`, store the
     answers;
  4. compute `ai_score.score(answers)`, store `ai_score` + `ai_score_version`.
  No API key and a cache miss → a clear error (job fails with "no Gemini API key configured"); a
  cache hit needs no key at all.
- Job kind `ai_rate` (file-scoped) registered on `app.state.jobs`; `rescore_stale(conn)` (178)
  runs at app start and after each job.
