# 219: Tuning preview DNG for X-Trans (6x6 CFA) sensors

## What's wanted

A RAF produces a downscaled, still-mosaiced preview DNG so the tuning sliders render locally, as
for a DNG/PEF.

## Design

- `_generate` currently raises `Unsupported` unless `raw.raw_pattern.shape == (2, 2)`. Generalise to
  the pattern period `P` (2 for Bayer, 6 for X-Trans; anything else stays `Unsupported`).
- Effective pattern: `eff[r][c] = pattern[(r + top_margin) % P][(c + left_margin) % P]` (the Fuji
  visible area has `top_margin=6`, which is a multiple of 6 here but the formula must not assume it).
- `_bin_mosaic(img, factor, period)`: bin each of the `P*P` phases independently; crop to a multiple
  of `P*factor` first so the pattern stays periodic. The doubling `factor` loop is unchanged
  (6032x4028 → factor 4 → 1506x1002 with a 6x6 pattern intact).
- Tags: `CFARepeatPatternDim` = (P, P), `CFAPattern` with P*P bytes (R=0 G=1 B=2 via
  `color_desc`), `BlackLevelRepeatDim` = (P, P) and `P*P` `BlackLevel` values (ticket 106's lesson).
  `color_desc` for X-Trans is `RGBG`, same lookup as Bayer.
- Make/Model: the source's EXIF is no longer reachable through Pillow for a RAF; use 218's reader
  (factor a shared "make/model/orientation of this RAW" helper out of `_source_exif`/`_make_model`).
  Ticket 106 found LibRaw only applies its camera colour table when Make/Model are present and
  recognised — FUJIFILM X-H1 is in LibRaw's table, to be confirmed empirically.
- **Verification is the point of this ticket** (that is how 106's bugs were found): compare
  `rawpy.postprocess` of the generated DNG with the same settings against the original RAF (mean RGB
  within a few %, no colour cast), and render it in the vendored LibRaw-Wasm in a browser. LibRaw's
  DNG loader must treat a 6x6 `CFAPattern` as X-Trans (filters=9) and the wasm build must include an
  X-Trans demosaic; if either fails, record that in Findings and decide (e.g. a pre-demosaiced
  fallback for X-Trans, or leave the server `raw_preview` path) before going further.
- `rawTuning.mapSettings`/`previews._postprocess_kwargs` parity: the demosaic option list may offer
  Bayer-only algorithms (AHD, DCB…) that LibRaw ignores or rejects for X-Trans — check what rawpy
  does for `demosaic_algorithm` on a RAF and what the UI offers.
