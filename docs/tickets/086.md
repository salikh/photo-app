# 086: "This folder" / "this folder + subdirectories" toggle for the grid

- Type: task
- Status: done
- Priority: not now (user request 2026-09-23)
- Related: [087](087.md) (fav/tag filter buttons — the main reason this is worth building: a tag
  or fav filter is far more useful over a whole subtree than one folder at a time), [088](088.md)
  (batch selection/actions "across folders if the current view is subdir-enabled" depends on this)
- Refs: `photoapp/library.py` (`list_photos`, `filter_counts`, `_prefix_range` — the subtree
  prefix-range scan `list_dirs` already uses for its nested-folder counts, but `list_photos`
  restricts to direct children via `instr(substr(rf.path, ...), '/') = 0`), `photoapp/static/route.js`
  (`href`, `parse` — the route/query-string shape), `photoapp/static/app.js` (`filterRow`,
  `renderHeader`), `photoapp/static/grid.js` (`loadFolder`, `loadRest`)

Right now every filter/sort/count in the folder view (`list_photos`, `filter_counts`) only looks at
Photos directly in the current directory. Add a toggle — "just this directory" vs. "this directory
and subdirectories" — so a filter (especially [087](087.md)'s fav/tag filters) can be applied
across a whole subtree at once, e.g. "show me every ★5 in 2024" rather than folder by folder.

The user's own framing: a toggle now; **do not** build automatic switching into subdir mode when a
filter is applied — they said they'll try the manual toggle first and "may consider" auto-switch
later. Don't build the auto-switch speculatively.

## Design notes

- **Where the toggle lives**: `route.js`'s route shape gains a new field (e.g. `recursive`,
  boolean) alongside `dir`/`filter`/`sort`/`photo`, so it round-trips through `href`/`parse` the
  same way sort and filter already do — replaceState like `filterRow`'s filter switch (ticket
  077), not a Back-button stop.
- **Server side**: `list_photos` already computes a subtree-covering `(lo, hi)` prefix range via
  `_prefix_range` for `list_dirs`'s nested counts — `list_photos`'s own `where` clause additionally
  requires `instr(substr(rf.path, ?), '/') = 0` (direct child only). A recursive flag just needs to
  skip that one condition and its `args` slot. `filter_counts` needs the identical change (same
  file, same reasoning as `docs/design/databases.md`'s note in `list_photos` about counts having to
  agree with what clicking a filter button actually shows) — do both together or the two go out of
  sync.
- **What passes through unaffected**: `list_dirs` (directory chips + their own subtree counts) is
  already subtree-aware and is a separate concern from the grid's own filter — don't conflate the
  two mechanisms even though they share `_prefix_range`.
- **The loupe's "next/prev in this folder" list** (`grid.loadFolder`/`loadRest`, which populate
  `state.photos` from the same `/api/photos` call the grid renders) should pick up subtree results
  automatically once the API honors the flag — no separate change expected there, but confirm the
  loupe's filename-only display (no directory shown per photo today) doesn't get confusing once a
  folder's grid can show photos from several different subdirectories at once; may need the path
  shown somewhere when recursive.
- **UI (decided)**: a toggle button/switch next to the sort `<select>` in `renderHeader`'s bar,
  mirroring `filterRow`'s replaceState pattern; labeled "This folder" / "This folder + subfolders".
