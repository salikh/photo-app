## What's wanted (as given)

The lens used with the picture: extract it from the image metadata, store it to the per-file
`.json` metadata cache, add it as a column in the database, and show it as an additional field in
the loupe's **Files** pane (next to the existing camera/focal/aperture/shutter/ISO line).

## Design overview (detail in each child ticket)

- **One new per-file field, `lens_model`.** Camera make/model (ticket 111) is the camera body; the
  lens is its own EXIF tag, `LensModel` (0xA434), in the Exif sub-IFD — the same place
  `FocalLength` already lives. A single text column, `files.lens_model`, is enough for "lens
  used"; `LensMake` (0xA433) is usually folded into the model string and is not asked for, so it is
  a non-goal here.
- **Extraction reuses the ticket 111 helper.** `read_lens_metadata` already reads focal length +
  camera make/model from one `img.getexif()` parse; `lens_model` is one more tag from that same
  sub-IFD, so `read_image_metadata`'s return tuple grows by one element and RAW files are covered
  for free (Pillow parses the EXIF header even when LibRaw supplies the dimensions).
- **The JSON cache follows the existing `REQUIRED_KEYS` mechanism, not a new one.** Adding
  `lens_model` to `metacache.REQUIRED_KEYS` is exactly ticket 111's "a record missing a key added
  later is backfilled by re-reading that one file" path: the next scan with `write_metadata_json`
  (the default) reprocesses every directory whose cache predates this field, re-reads each file's
  EXIF once, writes the new key to `<name>.json`/`index.json`, and upserts the `files` row. No
  separate backfill script is needed — this is deliberately the same choice ticket 111 made for
  `focal_length`/`camera_make`/`camera_model`, so there is no new operational step for the real
  library.
- **No new job kind, endpoint, or UI surface.** The field rides the existing scan → `files` →
  `/api/photos/{id}` → Files-panel pipeline end to end; the only frontend change is one more item
  in `cameraMetaText`'s parts list.

## Non-goals

- **LensMake / LensSpecification / lens serial number.** One display string is what was asked for;
  the model string already carries the make on the lenses this library has. Add later if a real
  lens needs it.
- **A dedicated backfill script** (the `backfill_exif.py` model). Existing rows are backfilled by
  the scan cache as in ticket 111; forcing a full library re-read outside a scan was explicitly
  not wanted there and is not needed here.
- **New search/filter/sort by lens.** Only display, as asked.
