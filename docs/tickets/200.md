# 200: The rating filter and the tag filter are independent (ANDed)

- Type: task
- Status: done
- Priority: user request 2026-10-08
- Refs: `photoapp/library.py` (`split_filter`, `list_photos`, `filter_counts`), `photoapp/api.py`,
  `photoapp/static/{route,app,grid,filters,loupe}.js`

## What's wanted

The stars/unrated/rejected filter and the tag filter were one setting (`filter=tag:x` replaced
`filter=rating:4`). They should combine with AND.

## Design

- Server: `/api/photos` and `/api/photos/counts` take `tag=NAME` next to `filter=`; the conditions are
  ANDed, counts honour the tag (so a button's number still equals what clicking it shows). A legacy
  `filter=tag:X` is read as `filter=all&tag=X` (`library.split_filter`); an explicit `tag` wins.
- URL: `#/dir?filter=rating:4&tag=vacation`; an old `filter=tag:x` link is rewritten on parse.
- UI: the tag dropdown only sets the tag (its first option clears it, "all tags"), the rating buttons
  and "more…" only set the rating filter; both survive the other, folder changes and rename. The loupe's
  filter button reads `filter: ★4 · tag: vacation`; its picker still lists rating filters (options
  disabled when the photo would not match rating AND tag); clicking a tag chip changes only the tag.
  A photo that stops matching either filter leaves the view (`filters.matchesRoute`). Folder Rename and
  Delete-review buttons are hidden while a tag filter is active (they act on the whole folder).
