# 084: Show camera metadata in the Files detail view

- Type: task
- Status: open
- Priority: not now (user request 2026-09-23)
- Blocked by: [083](083.md) (schema + extraction/backfill for aperture, shutter speed, ISO must
  exist before this can display them)
- Related: [082](082.md) (the same panel this adds to)
- Refs: `photoapp/static/loupe.js` (`openFiles`, the per-file `.file` row — currently shows
  `${width}×${height}  ${path}`), `photoapp/library.py` (`photo_detail`'s `files` list — needs the
  new columns added to its `SELECT`)

On the Files detail view (`openFiles` in the loupe, `I` or the `files` HUD button), show each
file's camera metadata: aperture (f-number), shutter speed, ISO, and exif date. `exif_date` is
already in the database and just needs surfacing; aperture/shutter speed/ISO depend on
[083](083.md) actually extracting and storing them first — **do not start this until 083's columns
exist**, there is nothing to display otherwise.

## Scope

- `library.photo_detail`'s `files` query (`photoapp/library.py`) needs the new columns added to
  its `SELECT` so they reach the frontend at all.
- `loupe.js`'s per-file row (`f.width || '?'}×${f.height || '?'}  ${f.path}` today) gets the new
  fields appended, formatted for humans — e.g. `f/2.8  1/250s  ISO 400  2019-07-04 14:22` — using
  whatever shutter-speed display formatting [083](083.md)'s design settled on.
- A file with missing/absent EXIF for one or more fields (common for scans, screenshots, exports)
  should degrade gracefully (omit that field, not show a confusing zero or `null`) — same
  tolerance the existing `width || '?'` already shows for missing dimensions.
