## What's wanted (as given)

"Add support for importing Fuji raw files (RAF). The rules for JPG+RAF should be similar to
JPG+DNG. RAF should also support conversion to a downscaled DNG for client-side raw conversion
tuning."

## What already works (measured 2026-10-11 on the sample directory)

- `.raf` is already in `IMAGE_EXTENSIONS` and `RAW_EXTENSIONS`; `grouping._split_groups` keys on
  `fileinfo.is_raw`, so a `DSCF1001.JPG` + `DSCF1001.RAF` pair is already one Photo with the RAW as
  original and the JPG as its camera file — the same rule as JPG+DNG. Ticket 220 locks this in with
  tests rather than changing it.
- LibRaw reads the RAFs (rawpy): 6048x4038 raw, visible 6032x4028, crop 5998x3997 (the camera JPG
  is 6000x4000), embedded JPEG preview 1920x1280, `rawpy.postprocess` full-size ~7 s.

## What does not work

- **EXIF.** A RAF is not a TIFF (`FUJIFILMCCD-RAW ` header, then an embedded EXIF JPEG, a RAF-specific
  CFA header and the raw data), so Pillow cannot open it and epic 160's TIFF-IFD fallback does not
  apply. Every RAF row gets date/aperture/shutter/ISO/focal length/camera/lens all NULL (and thus
  sorts by file mtime, not shot time). → 218.
- **Tuning preview DNG.** The X-H1 has an X-Trans sensor: a 6x6 colour-filter pattern.
  `raw_preview_dng._generate` raises `Unsupported` for anything but 2x2 Bayer, so RAF has no local
  tuning (it falls back to the slow server `raw_preview`). → 219.
- **Huge size.** The embedded preview is 1920 px, so an untouched RAF's "Huge" is not full size,
  unlike a DNG's. → question ticket 221.

## Non-goals

- Fuji film simulations, in-camera crop/RAF-specific tags beyond what LibRaw applies.
- Other X-Trans-specific render options beyond what rawpy/LibRaw-Wasm already expose.
- Video (`DSCF1020.MOV` is handled by epic 184 as for any camera).
