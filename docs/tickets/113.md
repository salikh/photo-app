# 113: Active job reporting on the Jobs page

- Type: task
- Status: done
- Related: [064](064.md) (jobs UI and status endpoint), [066](066.md) (background jobs)
- Refs: `photoapp/populate_thumbs.py`, `photoapp/jobs.py` (or background job queue runner),
  `photoapp/api.py`, `photoapp/static/jobs.html` / `jobs.js`

## What's wanted

On the "Jobs" page, show whether the worker is active, and what specific job or file the worker is
busy with.

- State indicator: Idle vs Active / Busy.
- Detail: Show what job type, file path/ID, and start time / duration the worker is currently
  working on.

## Outcome

Landed. A new nullable `jobs.started_at` (migration) is set when `_claim` marks a job `running`
(and cleared when `start()` requeues a job left running by a restart). `JobQueue.active()` returns
`{'busy': bool, 'running': [...]}` across every kind in the shared table, each entry carrying id,
kind, file_id/target, the resolved `files.path`, created/started timestamps and a duration measured
from `started_at` (created_at for pre-migration rows). `/api/jobs` now includes it, and the Jobs
page renders a `Worker: Idle` / `Worker: Active — kind path (duration)` line above the summary.
Tests in `tests/test_jobs.py` (blocking-handler active reporting, path resolution, API payload) and
a Jobs-page e2e check.
