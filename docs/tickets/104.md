## What's wanted

Given [103](103.md)'s answer for *how* to produce a lossy, reduced DNG from an original RAW file,
this ticket does the actual generation and caching:

- Generate once per RAW file (not per tuning session), cached the same way `thumbs.py` caches a
  size — looked up before regenerating, never overwritten once made (this project's existing
  cache convention, see `thumbs.clear`'s comment: "every render path in this codebase deliberately
  never overwrites an existing one").
- A new endpoint (or a new size-like keyword on an existing one — TBD, whichever reads more
  naturally once 103 is answered) that [105](105.md)'s client fetches once when the tuning UI
  opens for a file.
- Decide whether generation happens inline on first request (like `thumbs.make`'s cheap paths) or
  via the job queue (like a RAW with no usable embedded preview) — depends on how slow 103's
  chosen technique turns out to be; measure before choosing, the same way [093](093.md) measured
  before adding its optimization.
- Cache invalidation: this artifact depends only on the *original* file, never on `raw_settings`
  (unlike the committed thumbnails, its whole point is to be tuned *before* any setting is
  chosen) — so, unlike `raw_settings.set`'s `thumbs.clear`, saving new settings must **not** clear
  this cache.

## How it was built (103's decision, made concrete)

`rawpy.raw_image_visible` (the real Bayer mosaic) is downsampled by binning same-CFA-phase pixels
together in powers of 2 (each of the 4 phases -- R, G, G2, B -- binned independently, so the 2x2
pattern stays intact and periodic) until under `MAX_DIM` (1600px long edge), then written out as a
DNG via `tifffile`'s `extratags` (`CFAPattern`, `BlackLevel`, `WhiteLevel`, `ColorMatrix1`,
`AsShotNeutral`, ...), sourced from rawpy's own `raw_pattern`/`color_desc`/`black_level_per_channel`/
`white_level`/`rgb_xyz_matrix`/`camera_whitebalance`. A real Pentax K-5 DNG (15.7MB) produces a
2.0MB preview DNG (1236×820, bin factor 4).

Verified against the real thing, not just rawpy: [LibRaw-Wasm](https://github.com/ybouane/LibRaw-Wasm)
1.6.0 vendored into `photoapp/static/vendor/libraw-wasm/` (fetched from jsdelivr/unpkg -- no npm on
this machine) was driven in a headless-Chrome smoke test (`open()` with real settings, then
`imageData()`/`rawImageData()`) against a generated preview DNG and decoded it correctly.
