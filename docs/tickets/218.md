## What's wanted

`read_image_metadata` on a RAF returns the real date, aperture, shutter, ISO, focal length,
35mm focal length, camera make/model and lens, as it does for the JPG next to it.

## Design

- RAF layout: 16-byte magic `FUJIFILMCCD-RAW `, then big-endian offset/length pairs at byte 84
  (JPEG offset, JPEG length), 92 (CFA header), 100 (raw data). The JPEG is a complete JPEG whose EXIF
  has IFD0 + Exif sub-IFD (verified: DateTimeOriginal, Make, Model, ISO present).
- New `fileinfo.read_exif_from_raf(filepath)` returning the same nine-tuple as
  `read_exif_from_tiff`: read the header, slice the embedded JPEG, open it with Pillow from a
  `BytesIO` (`Image.open` reads only the headers/EXIF; no decode) and reuse `read_exif_date`/
  `read_camera_metadata`/`read_lens_metadata`. All `None` on any failure.
- `read_image_metadata`'s Pillow-failure branch for RAW files dispatches on the magic bytes: RAF →
  `read_exif_from_raf`, else the TIFF fallback. `read_exif_focal_length_35mm` (the cheap scan path)
  gets the same dispatch.
- `FNumber` of a manual lens is the EXIF "undefined" value, which Pillow reads as a NaN rational
  (the sample's JPGs have `aperture = nan` too). Make `_exif_rational_to_float` return `None` for a
  non-finite result so NaN is never cached or stored (`json.dumps` would write the invalid-JSON token
  `NaN`).
- Stale records: a RAF cached before this ticket has all-None EXIF; epic 160's `record_is_stale`
  keys on `mime_type == "image/x-raw"`, but `mimetypes.guess_type('x.raf')` is `None`, which
  `read_raw_size` already maps to `image/x-raw`, so the rule should already apply — verify, and add
  a test.
- `backfill_exif` already calls `read_image_metadata`, so it fills RAF rows with no change; verify
  in a test and mention RAF in `docs/operations.md`.

## Outcome

Landed. `fileinfo.read_exif_from_raf` slices the embedded JPEG (offset/length at byte 84 of the
`FUJIFILMCCD-RAW ` header) and reads it with the same Pillow-based readers a JPEG uses;
`read_exif_fallback` dispatches RAF vs TIFF and is used by `read_image_metadata` and
`read_focal_length_35mm`. `_exif_rational_to_float` now returns `None` for non-finite values (the
manual-lens `FNumber` 'undefined' was reading as NaN, also for the sample's camera JPGs). The
"could not decode" message for a RAW with a fallback is now verbose-level, not a warning. The stale
record rule and `backfill_exif` needed no change (tests added for both). Real sample:
`('image/x-raw', 5998, 3997, '2026-10-11 17:23:10', None, 1/28, 51200, 50.0, 'FUJIFILM', 'X-H1',
None, 75)`. The lens stays `None` — the X-H1 body records no LensModel with this manual lens.
Full non-e2e suite green (586 passed).
